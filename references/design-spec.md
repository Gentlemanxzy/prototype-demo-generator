# 智慧水务数字孪生大屏设计规范

本文档用于约束智慧水务、园区水务、水厂数字孪生可视化 Demo 的视觉设计与前端实现。

当用户提供 Figma 链接、原型图、页面截图或导出图时，原型中的布局、颜色、透明度、面板层级、字号、间距、阴影、发光和组件形态优先级最高；本文档作为默认规范与落地校准表使用。

## 1. 设计定位

界面应呈现“数字孪生园区 / 智慧水务监测平台”的专业感：

- 深色实景底图或三维鸟瞰为主视觉。
- 业务数据悬浮在画面边缘，不遮挡核心场景。
- 面板采用半透明玻璃质感，强调可读性，不堆叠过度装饰。
- 主色以科技蓝为核心，辅以青色、白色、橙色、红色表达状态。
- 数据、告警、设备、楼栋、管线、巡检等信息要能被快速扫描。
- 视觉效果服务业务讲解，避免只做装饰性的科技风。

## 3. 画布与适配

业务大屏统一以 `1920 × 1080` 为设计基准。

前端适配规则：

- 按浏览器窗口等比缩放。
- 居中显示业务画布。
- 不改变核心业务模块的相对坐标。
- 不因窗口变化重排顶栏、侧栏、右栏、底栏和中央场景。
- 安全边距左右建议 `24px`。
- 左侧导航距画布左侧固定为 `24px`。
- 右侧固定信息栏与画布右边保持 `24px` 间距。
- 右侧内容距离画布右侧固定为 `24px`，优先使用 `right: 24px` 或 `x=1920-24-内容宽度` 计算。
- 底栏固定贴底，右侧面板底部与底栏之间保留约 `46px` 可视空间。

推荐实现方式：

```css
.screen-stage {
  width: 1920px;
  height: 1080px;
  transform-origin: top left;
}
```

## 5. LayoutFrame 布局框架库

当前参考 Figma 节点：

- `25590:11482`：常用深色右侧布局。
- `25590:11515`：常用深色右侧布局 + 中央弹窗。
- `25590:11552`：左右双侧图表栏布局。
- `25590:11587`：右侧布局 + 左侧二级拆楼菜单。
- `25590:11620`：右侧布局 + 底部一级 / 二级菜单。

这些节点用于约束可能出现的大屏布局和框架，不固定具体业务文案。后续生成 Demo 时，应先判断当前业务属于哪一类框架，再套用对应结构。

### 通用框架约束

- 画布固定 `1920 × 1080`。
- 顶栏高度 `64px`，底栏高度 `36px`。
- 主内容区统一从 `x=24 y=88` 开始，宽 `1872px`，高 `932px`。
- 主内容区内部模块横向间距 `24px`。
- 右侧内容距画布右侧固定 `24px`。
- 右侧图表 / 数据栏常用宽度 `380px`，因此单右栏布局右侧栏位置为 `x=1516 y=88 w=380 h=932`。
- 主场景区高度与右侧栏保持一致，默认 `932px`。
- 所有框架中的搜索、告警、图例、时间轴、拆楼器等浮层，都应按 `4px` 倍数微调。

### 框架类型

| 框架 | Figma 节点 | 结构 | 关键尺寸 / 位置 | 适用场景 |
|---|---|---|---|---|
| 单右栏常用布局 | `25590:11482` | 中央场景 + 右侧图表栏 | 主内容 `x=24 y=88 w=1872 h=932`；右栏 `w=380 right=24`；场景与右栏间距 `24` | 默认总览、监测看板 |
| 弹窗叠加布局 | `25590:11515` | 单右栏布局 + 中央弹窗 | 弹窗宽约 `1072px`，图片内容比例 `16:9` | 视频、图片、详情大弹窗 |
| 左右双栏布局 | `25590:11552` | 左图表栏 + 中央场景 + 右图表栏 | 左栏 `w=380`，右栏 `w=380 right=24`，栏与场景间距 `24` | 数据密度高、左右对比分析 |
| 左侧二级菜单布局 | `25590:11587` | 中央场景 + 右栏 + 左侧二级拆楼菜单 | 二级菜单约 `x=30 y=279 w=184 h=550`；右栏仍 `w=380 right=24` | 楼栋、楼层、区域下钻 |
| 底部菜单布局 | `25590:11620` | 中央场景 + 右栏 + 底部一级 / 二级菜单 | 一级菜单约 `1128 × 64`，二级菜单约 `1128 × 40`，底部菜单位于场景底部上方 | 工艺步骤、时间轴、漫游路径、模式切换 |

### 顶栏框架

- 常规顶栏三段：标题区 `420px`、一级菜单区 `864px`、天气 / 时间 / 用户区 `540px`。
- 底部菜单布局中，顶部可只保留标题区和天气 / 时间 / 用户区，一级菜单移入底部。
- 标题区、一级菜单区和用户信息区的具体内容跟随业务变化，尺寸结构优先保持。
- 顶栏内部文字与控件垂直居中，整体高度不超过 `64px`。

### 主场景与右侧栏

- 单右栏布局计算公式：右侧栏 `x = 1920 - 24 - 380 = 1516`。
- 主场景宽度：`1872 - 380 - 24 = 1468px`。
- 右侧栏高度在框架示意中为 `932px`，在真实页面中可根据底部状态栏和内容数量使用 `910-932px`，但右边距必须保持 `24px`。
- 右侧栏承载图表、列表、指标卡、告警和详情，不承载全屏主操作。

### 左右双栏

- 左右栏均建议 `380px` 宽。
- 左栏位置 `x=24 y=88`，右栏位置 `x=1516 y=88`。
- 中央场景宽度约 `1064px`，左右与侧栏间距均为 `24px`。
- 适用于同屏需要展示两个维度数据的页面，例如“运行态势 + 水质趋势”“设备状态 + 告警统计”。

### 弹窗布局

- 弹窗叠加在主场景上方，不能遮挡右侧固定图表栏。
- 大图 / 视频类弹窗内容比例优先 `16:9`。
- 弹窗宽度可参考 `1072px`，高度根据内容比例和标题栏计算。
- 弹窗背景使用深色半透明面板，需保持主场景弱可见。

### 拆楼器与下钻菜单

- 内置拆楼器可作为 `72px` 宽的竖向控件，贴近场景边缘。
- 二级拆楼菜单可使用 `184px` 宽、约 `550px` 高的竖向浮层。
- 拆楼菜单距左优先使用 `24px / 30px` 视觉落位；如与左侧导航冲突，以左侧导航 `24px` 强约束为准，菜单向右避让。
- 楼栋、楼层、区域切换会联动中央场景和右侧数据栏。

### 底部一级 / 二级菜单

- 底部一级菜单可使用 `1128 × 64px`。
- 底部二级菜单可使用 `1128 × 40px`，位于一级菜单上方。
- 底部菜单距离底栏至少保留 `24px` 视觉缓冲，避免贴底拥挤。
- 底部菜单适合承载流程步骤、漫游路径、时间轴和模式切换。

### 辅助浮层

- 搜索区常用 `302 × 36px` 输入框 + `100 × 36px` 按钮，间距 `12px`。
- 风险提示告警区域常用 `400 × 54px`，边框可使用红色虚线或告警色描边。
- 图例区域常用 `100 × 100px`，优先放在左下角，不遮挡主场景关键点。
- 时间轴区域常用高度 `64px`，宽度可按业务使用 `876px / 1128px`。

## 6. 网格与间距

基础网格使用 `4px` 倍数体系，主要间距必须优先落在 `4px` 的整数倍上：

| Token | 值 | 用途 |
|---|---:|---|
| `space.1` | `4px` | 图标与文字、细小内部间距 |
| `space.2` | `8px` | 按钮间距、列表间距 |
| `space.3` | `12px` | 浮层、筛选器、按钮组的常规内边距 |
| `space.4` | `12px` | 顶栏导航间距、右上时间组间距 |
| `space.5` | `16px` | 标题左边距、面板常规内边距 |
| `space.6` | `24px` | 大屏安全边距、侧栏上下内边距 |
| `space.8` | `32px` | 大区块间距、图表内边距上限 |

强约束：

- 间隔距离主要使用 `4px` 的倍数，例如 `4 / 8 / 12 / 16 / 20 / 24 / 32px`。
- 非 `4px` 倍数只允许来自 Figma 实测的特殊坐标或视觉微调，不作为通用规范沉淀。
- 顶栏内容垂直居中，标题区域 `x=24 y=16 h=32`。
- 右侧面板内横向内容宽度默认 `348px`，即左右各 `16px`。
- 右栏卡片之间间距 `12px`。
- 左上筛选器按钮行列间距 `8px`。
- 筛选器上下两组按钮之间用 `1px` 分割线，分割线上下各 `10px`。

## 8. 字体规范

字体族：

- 中文：`PingFang SC` / `Noto Sans SC` / `Microsoft YaHei`
- 英文与数字：`Open Sans` / `Roboto` / `Arial`
- Tooltip 可使用 `Inter`

| 类型 | 字号 | 字重 | 行高 | 用途 |
|---|---:|---|---:|---|
| 平台标题 | `24px` | Bold | `24px` | 顶部平台名称 |
| 一级导航 | `16px` | Bold | `16px` | 看板、工艺、漫游、管线、巡检、演练 |
| 面板标题 | `14-16px` | Bold | `24px` | 右侧卡片标题 |
| 正文 / 按钮 | `14px` | Medium / Bold | `20-22px` | 筛选按钮、日期、用户 |
| 图表标签 | `10-12px` | Regular / Medium | `12-16px` | 单位、图例、坐标轴 |
| 关键数字 | `18-24px` | Bold | `20-28px` | 今日水量、实时数值 |
| 底部英文 | `10px` | Bold | `16px` | 平台英文标识，字距 `1.5px` |

限制：

- 大屏正文最小建议 `12px`，核心业务正文不低于 `14px`。
- 地图 / 楼栋标签主文字不低于 `14px`。
- 右侧面板中的图例、单位可用 `10px`，但需要保证对比度。

### 文字与文字框

文字规范只控制以下属性：

- 字体族。
- 字号。
- 字重。
- 颜色。
- 行高。
- 文本容器尺寸、内边距、对齐方式和选中 / hover 视觉效果。

不固定具体文案；平台名称、一级导航、指标名称、楼栋名称、水质指标、告警类型等均应跟随真实水务业务内容变化。

文字框设计要求：

- 文字框高度优先使用 `24 / 28 / 32 / 36 / 48px`。
- 横向内边距优先使用 `8 / 12 / 16px`。
- 普通标签文字居中，业务列表文字左对齐。
- 文字框背景以透明、弱半透明或品牌蓝选中态为主。
- 选中态必须通过背景、底线、描边或文字颜色变化表达，不能只依赖字号变化。

### MetricCard 指标卡片通用样式

参考节点：`796:10152`。

指标卡片用于概况、KPI、状态统计和右侧详情指标组。

必须统一：

- 卡片背景、透明度、描边、圆角、标题栏、内容内边距和模块间距。
- 指标名称、数值、单位、同比/环比、状态标签的字号和颜色层级。
- 图标容器尺寸、图标与文字间距、数值与单位对齐方式。
- 指标名可以单独一行；指标数值和单位必须包裹在同一个数值行中，不得拆成上下两行。

字体约束：

- 卡片标题/指标名称默认 `12-14px`。
- 普通数值默认 `16-22px`。
- 右侧卡片数值默认不得超过 `24px`，除非当前 UI 图明确是大数字。
- 单位、说明和辅助文字默认 `10-12px`。

结构约束：

- 指标项必须采用“指标名行 + 数值单位行”的结构。
- 允许：`<div class="metric"><span class="metric-label">温度</span><span class="metric-value-row"><b class="metric-value">18.5</b><span class="metric-unit">℃</span></span></div>`。
- 不推荐：`<div class="metric"><span>温度</span><b>18.5</b><span>℃</span></div>`，因为数值和单位作为平级元素容易被 flex/grid 或宽度挤压成换行。
- `.metric-value-row` 必须使用 `display: inline-flex` 或 `display: flex`，`align-items: baseline`，`gap: 2-4px`，`white-space: nowrap`。
- `.metric-value` 和 `.metric-unit` 必须 `white-space: nowrap` 且 `flex-shrink: 0`，保证 `18.5℃`、`3000m³/h`、`7.2mg/L` 等数值单位同行展示。

不得：

- 为了填满卡片而放大字体。
- 用统一大号 KPI 样式覆盖当前 UI 图中的紧凑信息密度。
- 把不同层级的指标卡全部套成同一个 `.glass-panel`。

## 11. 场景规范

### 园区总览场景

必须包含：

- 园区或水厂鸟瞰主视角。
- 楼栋 / 构筑物标签。
- 园区边界线或管线轮廓。
- 右侧实时监测面板。
- 左侧场景与楼层筛选。
- 顶部平台导航与底部平台状态栏。

### 楼栋 / 设备下沉场景

必须包含：

- 被选中楼栋或设备的高亮轮廓。
- 可返回全景的入口。
- 楼层 / 区域筛选器。
- 右侧面板同步切换为对应楼栋、设备或水质详情。

### 水质监测场景

必须包含：

- 今日来水、今日出水、实时水位 / 水量等 KPI。
- 日处理负荷趋势。
- COD、氨氮、总磷、总氮、PH 等指标切换。
- 历史时间范围筛选。
- 进水 / 出水图例和趋势曲线。

### 通用交互点规则

- 所有交互控件优先使用 `4px` 倍数尺寸和间距。
- 常规控件高度优先使用 `28px / 32px / 40px / 48px`。
- 点击热区不小于 `32 × 32px`；侧栏主菜单热区不小于 `40 × 40px`。
- 图标型按钮图标常用 `16 × 16px`，菜单图标可用 `18 × 18px` 或 `24 × 24px`。
- 控件状态至少包含 `default / hover / selected / disabled`；开关、选择项额外包含 `on / off`。
- 置灰态文字和描边使用 `#A0A9C0` 或 `rgba(160,169,192,0.60)`，不要使用纯黑或低对比灰。
- 选中态优先使用品牌蓝 `#007FFF`，必要时叠加 `rgba(0,82,217,0.40)` 背景和 `#0052D9` 描边。

### 开关与选择项

- 开关分为短文案和多字文案两种：短文案整体 `92 × 28px`，多字文案整体 `124 × 28px`。
- Switch 本体保持 `48 × 28px`，文案与 Switch 间距 `12px`。
- 多选 / 单选容器统一 `124 × 32px`，左右内边距 `12px`。
- 带图标选择项需要保证图标、文字、勾选控件三者水平居中，不挤压文字。
- 小型勾选滑块尺寸 `14 × 14px`，用于紧凑列表或辅助筛选，不替代主要按钮。

### 搜索与输入

- 小搜索按钮：`74 × 32px`，可包含 `16px` 搜索图标和文字。
- 单图标搜索按钮：`32 × 32px`，适用于工具栏和输入框右侧。
- 面板搜索输入框：宽 `348px`，高 `32px`，与右侧面板内容宽度一致。
- 弹窗或宽面板搜索输入框：宽 `390px`，高 `32px`。
- 搜索状态包括：未搜索、搜索结果、光标闪烁、置灰。
- 输入框内边距优先使用 `12px`，图标与文字间距 `8px`。

### 日期选择器

- 日期选择器下拉容器单月宽 `280px`，双月组合宽 `560px`，高度 `314px`。
- 内边距 `16px`。
- 头部高度 `22px`，日期主体区域 `248 × 248px`。
- 日期单元格 `32 × 32px`，内部日期按钮 `24 × 24px`。
- 日期列间距约 `4px`，行高 `32px`，符合 `4px` 倍数。
- 日期选择器用于历史数据查询，不用于实时监控主状态切换。

### 反馈状态

- 全局通知用于操作后的轻量反馈，分为成功和失败。
- 通知图标使用 `24 × 24px`，文案居中，整体高度约 `92-94px`。
- Loading 支持小、中、大三种尺寸，以及左右布局、上下布局。
- 空状态图标默认 `100 × 100px`，文案字号 `14px`，按钮高度 `32px`。
- 空状态文案跟随业务，例如“暂无搜索结果 / 暂无告警 / 暂无设备数据”。

### 弹窗与详情浮层

- 小型信息弹窗：`216 × 136px`，用于点位快速信息。
- 图文信息弹窗：`332 × 184px`，左侧图片区 `100 × 120px`，右侧数据区。
- 右侧详情弹窗：`380 × 570px`，适合设备详情、运行信息和基础信息。
- 系统选择器弹窗：`772 × 492px`，适合大图、系统总览或地图选择。
- 弹窗标题栏高度统一 `48px`，标题左边距 `16px`，关闭图标 `16 × 16px`，右边距 `16px`。
- 弹窗内容区左右内边距优先 `16px`，内部信息块按 `4px` 倍数排列。
- 弹窗只在需要承载详情、选择或图片时使用，不用于普通指标展示。

### 展开侧栏与工具条

- 展开侧栏单行项高度 `40px`，宽度可用 `156px`。
- 展开项之间垂直间距 `8px`。
- 小型工具条按钮统一 `32 × 32px`，间距 `6px` 可落地调整为 `8px`。
- 播放 / 暂停按钮可使用 `80 × 32px`，状态分为 `on / off`。
- 展开侧栏与折叠侧栏必须保持同一图标体系和状态色。

## 13. 交互动效

| 交互 | 动效 |
|---|---|
| 顶栏导航切换 | `180ms ease-out`，背景渐入 |
| 筛选按钮切换 | `120ms ease-out`，背景与描边变化 |
| 楼栋选中 | `240-300ms ease-in-out`，边界线 / 建筑高亮过渡 |
| 侧栏 hover | `120ms ease-out`，显示 tooltip |
| 右侧面板切换 | `240ms ease-in-out` |
| 告警闪烁 | `1.2s infinite`，红色呼吸发光 |
| 数据刷新 | `200-300ms` 数字轻微滚动或高亮 |

动效要克制，告警和业务状态优先级高于装饰性光效。

## 15. 生成 Demo 时的执行要求
