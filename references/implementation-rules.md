# 实现规则

本文件统一约束页面实现阶段的视觉细节、交互逻辑、点位校准、多视口适配和禁止自由发挥边界。

## UI图优先

Figma/UI图决定布局、模块数量、视觉层级、坐标、字体、颜色、透明度和交互状态。设计规范只用于UI图缺失时补充。

不得用通用水厂风格替代UI图中的真实设计。

## 视觉细节

每页必须产出 `analysis/pages/<page-id>-visual-details.md`，记录：

- 背景图亮度、遮罩颜色、透明度、渐变压暗和层级关系。
- 顶部导航、左侧菜单、左右面板、弹窗、标签和图表容器的底色、透明度、描边、阴影、发光和圆角。
- 标题栏、内容区、角标、装饰线、分割线和选中态。
- 顶部导航、右侧卡片、标签、指标、单位、列表和辅助文字的字体家族、字号、字重、行高、颜色和密度。

无法精准取值时，应按 UI 图估算并标注“估算”。右侧卡片和顶部导航字体应偏紧凑，不得使用默认大屏夸张字号。

## 字体比例

当输入包含 Figma、UI图/原型图、截图或 Figma 导出图时，必须先产出 `analysis/typography-scale.md`，再编写主要 CSS 字体样式。

`analysis/typography-scale.md` 必须逐页登记：

- 页面基准尺寸和当前实现缩放策略。
- 顶部平台标题、顶部导航项、导航选中态、时间/状态区。
- 左侧菜单、一级/二级菜单、图标文字。
- 面板标题、面板副标题、卡片标题、指标名称、指标数值、单位。
- 表格表头、表格正文、列表标题、列表正文、辅助说明。
- 图表标题、图例、坐标轴、刻度、tooltip。
- 底图标签、设备点位标签、状态标签、按钮、弹窗标题和弹窗正文。
- 每类文字的字体家族、字号、字重、行高、颜色、字间距和来源：Figma / UI图估算 / 设计规范兜底。

优先级：

1. Figma 设计上下文中的真实字体值。
2. UI图/原型图或截图估算值。
3. `references/design-spec.md` 的字体规范兜底值。

兜底字号上限：

| 类型 | 建议范围 | 上限 |
| --- | ---: | ---: |
| 顶部导航项 | `13-16px` | `16px` |
| 顶部平台标题 | `18-24px` | `24px` |
| 面板标题 | `13-16px` | `18px` |
| 卡片标题/指标名称 | `12-14px` | `14px` |
| 普通正文/列表/表格 | `12-14px` | `14px` |
| 辅助说明/单位 | `10-12px` | `12px` |
| 右侧卡片数值 | `16-22px` | `24px` |
| 核心大 KPI | `20-28px` | `32px` |
| 图表坐标轴/图例 | `10-12px` | `12px` |
| 底图标签 | `12-14px` | `14px` |
| 弹窗标题 | `16-20px` | `20px` |

只有当UI图中对应文字明显超过上述上限，或用户明确要求更大字号时，才允许突破上限，并必须在 `analysis/typography-scale.md` 中说明依据。

禁止：

- 默认使用 `32px`、`36px`、`40px`、`48px` 等通用大屏字号。
- 因为是“数字孪生大屏”就放大导航、卡片标题、列表和右侧详情字号。
- 使用 `vw`、`vh` 或浏览器宽度直接驱动字体大小，导致非 1920 视口下文字失真。
- 为了填满卡片而放大文字，破坏UI图信息密度。
- 用设计规范兜底字号覆盖 Figma/UI图中更小、更紧凑的字号。

## 指标项结构

指标卡、数据卡、右侧详情指标组和点位标签中的指标项必须采用稳定结构，避免数值和单位换行。

推荐结构：

```html
<div class="metric">
  <span class="metric-label">温度</span>
  <span class="metric-value-row">
    <b class="metric-value">18.5</b>
    <span class="metric-unit">℃</span>
  </span>
</div>
```

推荐 CSS：

```css
.metric-value-row,
.data-value-row {
  display: inline-flex;
  align-items: baseline;
  gap: 2px 4px;
  white-space: nowrap;
  min-width: 0;
}

.metric-value,
.metric-unit,
.data-value,
.data-unit {
  white-space: nowrap;
  flex-shrink: 0;
}
```

实现要求：

- 指标名可以单独一行，例如“温度”。
- 指标数值和单位必须在同一行，例如 `18.5℃`、`3000m³/h`、`7.2mg/L`。
- 不得把指标名、数值、单位作为 `.metric` 下三个未分组的平级元素，避免布局引擎把单位挤到下一行。
- 不得给单位设置 `display: block`、`width: 100%` 或会强制换行的样式。
- 卡片空间不足时，优先缩小字号、调整 gap、减少字段或压缩单位文案，不得牺牲数值单位同行展示。
## 操作逻辑

必须产出 `analysis/interaction-logic.md`，登记：

- 顶部导航菜单项、目标页面/视图、默认选中、hover、选中态和点击行为。
- 左侧业务菜单点击行为。
- 底图标签、地图点位、设备热点或工艺节点的唯一 ID、名称、坐标、hover、选中态和点击后详情。
- 右侧详情、弹窗、筛选和列表行的触发、内容和关闭方式。

顶部导航和底图标签不得只做静态展示。点击不同标签时，右侧详情标题、指标、图表或状态必须对应变化。

来自需求文档的交互必须已在 `analysis/requirement-prototype-alignment.md` 中映射到UI图承载区域。

如果真实指标缺失，可以补充合理演示指标；不强制在界面明确标注“模拟数据”或“Mock 数据”。

## 图表实现

当 Figma、UI图/原型图或需求文档中出现图表时，必须产出 `analysis/chart-spec.md`，逐个登记：

- 图表 ID、所在页面、所在面板和图表类型。
- 横坐标含义、刻度、格式、单位和来源。
- 纵坐标含义、刻度、范围、单位和来源。
- 图例显示规则、系列名称、颜色、线型、柱宽、面积填充、网格线和数据标签。
- tooltip 内容、hover 状态和空数据状态。
- 指标切换、时间范围切换、筛选项、默认选中项和切换后的图表变化。
- 数据来源：Figma/UI图、需求文档、用户提供数据或模拟数据。

实现要求：

- 默认使用真实 ECharts 配置实现折线图、柱状图、面积图、饼图、环图和组合图；项目无法使用 ECharts 时，必须用同等能力的真实图表实现。
- 折线图、柱状图、面积图和组合图必须显式配置 `xAxis`、`yAxis`、`series`、`grid` 和 `tooltip`。
- ECharts 默认不配置可见 `legend`，或配置 `legend: { show: false }`。只有 Figma/UI图、需求文档或用户指令明确存在图例、多系列对比说明、图例切换入口时，才配置可见 `legend`。
- UI图或需求中明确横坐标、纵坐标、单位或指标名称时，必须在图表中显示，不得省略。
- 数据可以模拟，但坐标含义、单位、系列名称和切换逻辑不得缺失；不强制在图表区域或页面上明确标注“模拟数据”或“Mock 数据”。
- 图表中的指标切换、时间范围切换和筛选按钮不得只做静态展示；切换后 `series`、标题、单位、tooltip 或当前选中态必须同步变化。只有已明确实现可见图例时，才需要实现图例切换。
- 只有当UI图和需求都明确是无坐标装饰图时，才允许使用无坐标装饰图形。
- 禁止用几条 CSS 线、静态 SVG 路径、背景图或假柱子替代有业务含义的图表。

## 点位坐标

包含底图标签、地图点位、设备热点或工艺节点时，必须记录：

- UI图坐标 `x/y`。
- UI图画布尺寸。
- 相对百分比 `left/top`。
- 背景图显示方式：cover、contain、fill 或固定尺寸。
- 背景实际显示偏移。
- 最终 CSS 坐标。

使用 cover 时，必须考虑水平/垂直裁切偏移，避免标签整体上移、下移或左右偏移。

## 多视口适配

必须产出 `analysis/responsive-adaptation.md`，至少检查：

- `1920×1080`
- `1440×900`
- `1366×768`
- 当前浏览器窗口尺寸

页面不能只在 `1920×1080` 正常。普通浏览器窗口下不得出现明显上、左、右黑边，核心导航、菜单、面板、标签和可点击区域不得被裁切。

## 可预览入口

实现完成后必须检查 `workspace/index.html`：

- 纯静态项目：根入口直接承载页面。
- Vue/Vite 项目：先构建，再让根入口加载 `dist` 中的构建 JS/CSS，或跳转到 `dist/index.html`。
- 不得把只适用于开发服务器的 `/src/main.js` 作为根入口唯一脚本。
- 根入口、构建入口和最终说明中的预览地址必须一致，避免用户点击后看到空页面。

## Vue/Vite 构建防卡规则

使用 Vue/Vite 时：

- 先生成最小可运行项目并完成一次构建，再补页面细节。
- `@vitejs/plugin-vue` 必须以函数形式调用：`plugins: [vue()]`。
- 首版构建脚本优先使用 `vite build`，不要默认叠加 `vue-tsc -b`。
- 不要在首版同时引入 Tailwind、Element Plus、Three.js、Vue Router 和状态管理；除非用户明确要求或现有项目已使用。
- `npm install`、`npm run build`、预览服务和截图检查应分步执行；某一步失败时先修复该步，不要继续截图或反复重建。
- 页面很多时，先实现主布局、导航、多页面切换和 2-3 个关键页面，再补齐其余页面与状态，避免长时间卡在一次性全量生成。

## 禁止自由发挥

禁止：

- 新增UI图/Figma 中不存在的大模块、卡片、图表、表格、弹窗、工具栏或页面。
- 为了承载未映射需求而新增界面模块。
- 新增UI图和需求中未出现的通用三维工具栏，如主视角、空间剖切、测量、气候调整、时间回溯。
- 多个标签点击后显示同一个默认详情。
- 使用通用 GlassPanel、默认色值、默认字体或默认大 KPI 样式覆盖 UI 图。
- 合并多个UI页面为一个泛化页面。

## 页面计划约束

页面计划只能包含已登记到以下文件中的模块和交互：

- `analysis/prototype-page-map.md`
- `analysis/pages/<page-id>.md`
- `analysis/pages/<page-id>-visual-details.md`
- `analysis/typography-scale.md`
- `analysis/chart-spec.md`
- `analysis/interaction-logic.md`
- `analysis/requirement-prototype-alignment.md`
- `analysis/responsive-adaptation.md`

未登记内容不得进入代码实现。
