# 实现与输出规范

本文件统一约束页面实现、输出结构、技术栈、Vue/Vite、ECharts、指标项、点位、适配和禁止自由发挥边界。公司 UI 原始规范请读取 `design-spec.md`，本文只沉淀生成与落地规则。

## 1. 默认输出

默认生成一套可本地运行、可预览的前端项目。

推荐结构：

- 入口页或主布局。
- 顶部导航栏或平台顶栏。
- 多页面视图、路由或菜单切换。
- 模拟数据。
- 可复用业务组件。
- 图表组件。
- 水厂主题样式。
- `analysis/*.md` 分析文件。
- `generation-summary.md` 生成说明。

最终交付必须保证 `workspace/index.html` 能直接打开并看到页面。

## 2. 技术栈

默认使用 Vue 3、Vite 和 ECharts。

只在用户明确要求、现有项目已经使用，或页面确实需要时引入：

- TypeScript。
- Tailwind CSS。
- Element Plus。
- Three.js。
- Vue Router。
- 状态管理库。

如果用户明确要求纯静态页面，则使用 HTML、CSS、JavaScript、内置 SVG/CSS 图形或轻量 Canvas 图表。

## 3. Vue/Vite 规则

首版推荐 `Vue 3 + Vite + ECharts + CSS`。

必须使用可构建的最小配置：

```js
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";

export default defineConfig({
  base: "./",
  plugins: [vue()],
});
```

规则：

- `vite.config.js` 或 `vite.config.ts` 必须写 `plugins: [vue()]`，不得写 `plugins: [vue]`。
- `package.json` 必须包含 `@vitejs/plugin-vue` 和 `vite`，并包含 `dev`、`build`、`preview`。
- 默认使用 JavaScript：`src/main.js`、`src/App.vue`、`vite.config.js`。
- 只有用户明确要求 TypeScript 时，才使用 `vue-tsc`、`tsconfig` 和 `.ts` 入口。
- 构建脚本首选 `vite build`；不要默认叠加 `vue-tsc -b`。
- 多页面首版优先用组件化视图切换或轻量路由，不要为了演示强制引入复杂路由、状态管理或大型组件库。
- 先生成最小可运行项目并完成一次构建，再补页面细节。

Vue/Vite 项目完成构建后，根入口不得只保留 `/src/main.js` 这类开发服务器入口；必须改为加载 `dist` 构建产物、跳转到 `dist/index.html`，或将构建产物同步到根入口。

## 4. 多页面输出

如果输入包含多个 Figma 链接、多个 UI 图、多个页面编号、多个需求文档或多个模块，输出不得默认只有一个页面。

要求：

- 多个主页面必须具备可访问入口，例如顶部导航、左侧菜单、tab、视图切换或 Vue Router。
- 子页面、弹窗、抽屉、展开态、详情态必须挂在对应父页面下，由明确入口触发。
- 页面切换时必须同步顶部导航或左侧菜单选中态。
- 首页只能作为默认入口，不得替代其他已提交页面。
- 最终回复和 `generation-summary.md` 必须列出已生成主页面、子页面、状态页和暂缓页面。

## 5. 高保真实现

生成页面必须保持：

- 顶部导航栏或平台顶栏，除非 UI 图明确没有。
- UI 图布局、模块数量、主要视觉比例和背景构图。
- 颜色关系、面板透明度、层级、边框、阴影和发光。
- 信息密度和字号层级。
- 主要交互状态。
- 已映射到 UI 区域的需求文档操作逻辑。
- 当前轮用户明确要求的修改点。

禁止：

- 重新设计首页。
- 新增 UI 图中不存在的大卡片、图表、弹窗、工具栏或页面。
- 删除 UI 图中的主要模块。
- 合并多个 UI 页面。
- 使用通用后台布局替代 UI 图布局。
- 用统一 `.glass-panel` 覆盖 UI 图中不同层级的面板、弹窗、标签和图表容器。
- 使用通用字体、默认字号或过大的 KPI 字号替代 UI 图中的顶部导航、右侧卡片、标签和指标文字。

## 6. 字体与信息密度

当页面包含文字时，必须先产出 `analysis/typography-scale.md`，再编写主要 CSS 字体样式。

字体优先级：

1. Figma 设计上下文中的真实字体值。
2. UI 图/原型图或截图估算值。
3. `references/design-spec.md` 的字体规范兜底值。

兜底字号上限：

| 类型 | 建议范围 | 上限 |
| --- | ---: | ---: |
| 顶部导航项 | `13-16px` | `16px` |
| 顶部平台标题 | `18-24px` | `24px` |
| 面板标题 | `13-16px` | `18px` |
| 卡片标题/指标名称 | `12-14px` | `14px` |
| 普通正文/列表/表格 | `12-14px` | `14px` |
| 辅助说明/单位 | `10-12px` | `12px` |
| 右侧卡片数值 | `16-22px` | `24px` |
| 核心大 KPI | `20-28px` | `32px` |
| 图表坐标轴 | `10-12px` | `12px` |
| 底图标签 | `12-14px` | `14px` |
| 弹窗标题 | `16-20px` | `20px` |

禁止：

- 默认使用 `32px`、`36px`、`40px`、`48px` 等通用大屏字号。
- 因为是“数字孪生大屏”就放大导航、卡片标题、列表和右侧详情字号。
- 使用 `vw`、`vh` 或浏览器宽度直接驱动字体大小。
- 为了填满卡片而放大文字。
- 用设计规范兜底字号覆盖 Figma/UI 图中更小、更紧凑的字号。

## 7. 指标项结构

指标卡、数据卡、右侧详情指标组和点位标签中的指标名、数值和单位布局必须优先还原 Figma/UI 图，不得套用固定结构覆盖原图。

必须先在 `analysis/pages/<page-id>-visual-details.md` 或 `analysis/typography-scale.md` 记录每类指标项的布局关系：

- 指标名、数值、单位在 UI 图中是同行还是分行。
- 数值和单位是否同行、上下标、右对齐、底部对齐或独立列展示。
- 判断来源：Figma 实测、UI 图估算、用户指令或兜底。

当 UI/Figma 中指标名单独一行、数值和单位同行时，推荐结构：

```html
<div class="metric">
  <span class="metric-label">温度</span>
  <span class="metric-value-row">
    <b class="metric-value">18.5</b>
    <span class="metric-unit">℃</span>
  </span>
</div>
```

对应 CSS：

```css
.metric-value-row,
.data-value-row {
  display: inline-flex;
  align-items: baseline;
  gap: 2px 4px;
  white-space: nowrap;
  min-width: 0;
}

.metric-value,
.metric-unit,
.data-value,
.data-unit {
  white-space: nowrap;
  flex-shrink: 0;
}
```

规则：

- 如果 Figma/UI 图中数值和单位同行，实现中也必须同行，例如 `18.5℃`、`3000m³/h`、`7.2mg/L`。
- 如果 Figma/UI 图中数值和单位明确分行、分列或单位独立展示，实现中也应按原图分行、分列或独立展示。
- 无法判断 UI/Figma 布局时，默认采用“指标名行 + 数值单位同行”作为兜底，避免卡片因宽度不足产生意外换行。
- 不得把指标名、数值、单位作为 `.metric` 下三个未分组的平级元素后交给 flex/grid 自行挤压换行；必须根据分析结果显式包裹为数值行、分列组或分行组。
- 不得因为卡片空间不足产生与 UI 图不一致的被动换行。空间不足时，优先缩小字号、调整 gap、减少字段、压缩单位文案或按 UI 图重排。

## 8. 顶部导航和菜单

除非 UI 图明确没有顶部导航栏，否则所有水厂业务页面必须包含顶部导航栏或平台顶栏。

要求：

- 顶部导航栏通常位于业务画布 `x=0 y=0`，高度优先参考 UI 图；没有 UI 图时默认 `64px`。
- 顶部导航栏字体必须优先按 UI 图或 Figma 采样，包括字体家族、字号、字重、行高、颜色、字间距和选中态样式。
- 顶部导航栏不得被背景图、中央场景、canvas、地图、图表或全屏容器遮挡。
- 多页面项目切换页面时，顶部导航栏应持续存在，并同步当前页面选中态。
- 顶部导航栏必须支持点击切换页面或视图，不得只做静态装饰。
- 左侧业务菜单应根据页面清单自动生成菜单项，当前页面必须高亮，切换其他页面时同步更新。

## 9. 操作逻辑

必须产出 `analysis/interaction-logic.md`，登记：

- 顶部导航菜单项、目标页面/视图、默认选中、hover、选中态和点击行为。
- 左侧业务菜单点击行为。
- 底图标签、地图点位、设备热点或工艺节点的唯一 ID、名称、坐标、hover、选中态和点击后详情。
- 右侧详情、弹窗、筛选和列表行的触发、内容和关闭方式。

规则：

- 顶部导航和底图标签不得只做静态展示。
- 点击不同标签时，右侧详情标题、指标、图表或状态必须对应变化。
- 多个不同标签不得显示同一个默认详情。
- 来自需求文档的交互必须已映射到 UI 图承载区域。
- 真实指标缺失时，可以补充合理演示指标，不强制在界面标注“模拟数据”或“Mock 数据”。

## 10. ECharts 图表

当 Figma、UI 图或需求文档中出现图表时，必须产出 `analysis/chart-spec.md`。

必须记录：

- 图表 ID、所在页面、所在面板和图表类型。
- 横坐标含义、刻度、格式、单位和来源。
- 纵坐标含义、刻度、范围、单位和来源。
- 图例显示规则、系列名称、颜色、线型、柱宽、面积填充、网格线和数据标签。
- tooltip 内容、hover 状态和空数据状态。
- 指标切换、时间范围切换、筛选项、默认选中项和切换后的图表变化。
- 数据来源：Figma/UI 图、需求文档、用户提供数据或模拟数据。

实现要求：

- 默认使用真实 ECharts 配置实现折线图、柱状图、面积图、饼图、环图和组合图。
- 折线图、柱状图、面积图和组合图必须显式配置 `xAxis`、`yAxis`、`series`、`grid` 和 `tooltip`。
- ECharts 默认不配置可见 `legend`，或配置 `legend: { show: false }`。
- 只有 Figma/UI 图、需求文档或用户指令明确存在图例、多系列对比说明、图例切换入口时，才配置可见 `legend`。
- UI 图或需求中明确横坐标、纵坐标、单位或指标名称时，必须在图表中显示，不得省略。
- 数据可以模拟，但坐标含义、单位、系列名称和切换逻辑不得缺失。
- 指标切换、时间范围切换和筛选按钮不得只做静态展示；切换后 `series`、标题、单位、tooltip 或当前选中态必须同步变化。
- 禁止用 CSS 线条、静态 SVG 路径、背景图或假柱子替代有业务含义的图表。

## 11. 点位坐标

包含底图标签、地图点位、设备热点或工艺节点时，必须记录：

- UI 图坐标 `x/y`。
- UI 图画布尺寸。
- 相对百分比 `left/top`。
- 背景图显示方式：cover、contain、fill 或固定尺寸。
- 背景实际显示偏移。
- 最终 CSS 坐标。

使用 cover 时，必须考虑水平或垂直裁切偏移，避免标签整体上移、下移或左右偏移。

## 12. 大屏适配

水厂数字孪生大屏默认采用 `1920 × 1080` 固定业务画布，除非 UI 图本身是其他比例。

要求：

- 页面必须填满浏览器视口，不允许四周出现黑边。
- 默认使用 cover 缩放策略：在保持业务画布比例的前提下填满屏幕，允许边缘轻微裁切。
- 核心导航、菜单、指标、面板、弹窗、图表和操作区域必须放在安全区内。
- 业务画布居中显示并保持 UI 图中的空间关系。
- 核心模块不因窗口尺寸变化而重新排列。
- 必须产出 `analysis/responsive-adaptation.md`，并检查 `1920×1080`、`1440×900`、`1366×768` 和当前浏览器窗口。

## 13. 禁止自由发挥

禁止：

- 新增 UI 图/Figma 中不存在的大模块、卡片、图表、表格、弹窗、工具栏或页面。
- 为了承载未映射需求而新增界面模块。
- 新增 UI 图和需求中未出现的通用三维工具栏，如主视角、空间剖切、测量、气候调整、时间回溯。
- 多个标签点击后显示同一个默认详情。
- 使用通用 GlassPanel、默认色值、默认字体或默认大 KPI 样式覆盖 UI 图。
- 合并多个 UI 页面为一个泛化页面。
- 在界面中写“这里是图表”“待接入数据”等演示破绽。

## 14. 页面计划约束

页面计划只能包含已登记到以下文件中的模块和交互：

- `analysis/prototype-page-map.md`
- `analysis/pages/<page-id>.md`
- `analysis/pages/<page-id>-visual-details.md`
- `analysis/typography-scale.md`
- `analysis/chart-spec.md`
- `analysis/interaction-logic.md`
- `analysis/requirement-prototype-alignment.md`
- `analysis/responsive-adaptation.md`

未登记内容不得进入代码实现。
