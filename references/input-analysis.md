# 输入分析规范

本文件统一约束用户文本指令、Figma、UI图/原型图、链接清单、需求文档和页面结构的生成前分析。

## 输入优先级

1. 当前轮用户明确文本指令。
2. 历史对话中已确认且未被覆盖的用户规则。
3. Figma 节点结构、样式、尺寸、坐标、效果和资产。
4. Figma 导出图、UI图/原型图或页面截图。
5. 已映射到UI图承载区域的需求文档操作逻辑、数据要求、指标含义和演示重点。
6. 页面模板和通用设计规范。

如果当前轮用户明确指令与其他输入冲突，以当前轮用户明确指令为准，并记录到 `analysis/user-instructions.md`。

如果 Figma/UI图与需求、模板或设计规范冲突，以 Figma/UI图为准。

需求文档主要提供操作逻辑、数据要求、指标含义、字段口径和演示重点。除非用户明确指定，需求文档不得改变 Figma/UI图中的布局、视觉样式、模块数量、信息密度和页面结构。

## 用户文本指令

当用户提供自然语言指令、修改意见、反馈、限制条件或确认规则时，必须按 `references/user-instructions.md` 产出或更新 `analysis/user-instructions.md`。

必须识别：

- 明确指令：如“删除工具栏”“顶部导航要能切换”“图表必须有横纵坐标”。
- 约束规则：如“不要自由发挥”“以UI图/原型图为准”“缺少真实数据时可使用合理演示数据”。
- 覆盖关系：如“刚才那条作废”“按这个新截图来”“需求文档这部分不用”。
- 多轮改进：如“继续改上次生成的页面”“这个卡片再小一点”“这个交互没实现”。

当前轮用户指令不得被需求文档、模板或设计规范覆盖。

## Figma 链接清单

当输入中存在 `figma-links.txt`、`figma-links.md`、`figma-links.csv`、`links.txt`、`links.md` 或名称包含 `figma` 和 `link` 的清单文件，必须先读取全文。

必须：

- 提取所有 Figma URL，包括 `figma.com/design/`、`figma.com/file/` 和 `figma.com/proto/`。
- 保留链接前的页面编号、页面名称和备注，例如 `A1-场景总览:`。
- 提取 `node-id`，判断链接是节点链接、文件链接、proto 链接还是导出资源链接。
- 产出 `analysis/figma-link-map.md`。
- 将所有有效链接登记到 `analysis/prototype-page-map.md`。
- 不得只解析第一条链接。
- 不得因为某条链接没有在需求文档中出现就跳过。
- 同一业务模块下的多个 Figma 链接必须全部登记，判断它们分别是主页面、弹出层、抽屉、展开态、选中态、详情页、子页面、切换态还是 hover 态。
- 如果多个链接属于同一模块，应在 `analysis/prototype-page-map.md` 中建立父子关系或状态关系，而不是合并成一个泛化页面。

推荐格式：

```text
A1-场景总览:https://www.figma.com/design/xxx?node-id=25429-7480&m=dev
A2-运行监测:https://www.figma.com/design/xxx?node-id=25429-7658&m=dev
```

## UI页面映射

当存在多个 Figma Frame、UI图/原型图或状态图时，必须产出 `analysis/prototype-page-map.md`。

在生成页面代码前，必须先产出 `analysis/page-scope.md`，根据用户提交内容判断本次生成范围。不得因为用户没有明确写“多页面”就默认只生成一个页面。

页面范围判断依据：

- Figma 链接清单中的所有页面编号、页面名称、父页面、触发说明和 node-id。
- 上传 UI 图、截图或导出图的文件名，例如 `A1_看板_场景总览.png`、`A1-1_告警详情弹窗.png`。
- 需求文档文件名和文档内页面编号，例如 `A4_看板_水量监测_需求说明.md`。
- 需求文档中的“前端交互说明”“页面关系”“查看详情”“打开弹窗”“切换标签”“展开态”等描述。
- 用户当前轮明确说明的页面范围、重点页面和暂缓页面。

`analysis/page-scope.md` 必须登记：

| 页面编号 | 页面名称 | 类型 | 来源 | 父页面 | 触发入口 | 是否生成 | 实现方式 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| A1 | 场景总览 | 主页面 | Figma/UI图/需求 | - | 顶部导航 | 是 | 路由或可切换视图 |
| A1-1 | 告警详情 | 弹窗态 | Figma/UI图/需求 | A1 | 点击告警列表 | 是 | A1 内弹窗 |

页面映射必须区分：

- 主页面：场景总览、运行监测、水质监测、水量监测、设备管理等。
- 子页面：同一业务模块下的二级页面、报表页、详情页、历史记录页等。
- 状态页：展开态、选中态、弹窗态、抽屉态、详情态、轨迹态、hover 态等。
- 共享结构：顶部导航、左侧菜单、右侧面板、底部状态栏等。
- 暂缓状态：暂不实现时必须说明原因。

未登记到 `analysis/prototype-page-map.md` 的UI图/原型图、Frame 或链接不得被忽略。

Figma 页面生成规则：

- 所有有效 Figma 链接、Frame、UI图/原型图和状态图都是生成依据。
- 主页面必须生成为可访问页面、路由页面或可切换视图。
- 当识别出多个主页面时，必须实现顶部导航、左侧菜单、路由、tab 或等价的页面切换入口，不得只生成默认首页。
- 当识别出子页面时，必须通过父页面入口、路由、弹窗、抽屉或详情切换实现父子关系，不得无入口孤立生成。
- 弹出层、抽屉、展开态、选中态、详情态、子页面切换态必须作为交互状态实现；如果技术上暂缓，必须说明原因。
- 缺少需求文档说明时，也必须先按 Figma/UI图还原页面视觉和可见状态，再使用页面模板或合理模拟数据补充最低限度的演示内容。
- `analysis/requirement-prototype-alignment.md` 只能用来约束需求文档内容是否进入页面，不能用来过滤 Figma 已提供的页面、Frame 或状态。

禁止：

- 将多个主页面合并成一个长页面或一个泛化总览页。
- 只实现 Figma 链接清单或 UI 图列表中的第一张图。
- 因为某个页面缺少需求文档就不生成该页面。
- 因为某个需求文档缺少对应 UI 图就自由新增完整页面；这类内容应登记为未映射需求，除非用户明确要求补充。

## 需求与UI图对齐

当同时存在需求文档和 Figma/UI图时，必须产出 `analysis/requirement-prototype-alignment.md`。

需求文档只作为业务补充输入，重点提取：

- 操作逻辑。
- 数据要求。
- 指标含义。
- 字段、单位、范围和阈值。
- 图表横纵坐标含义、系列名称和切换规则。
- 筛选、弹窗、联动、状态变化和演示重点。

需求只有满足以下任一条件才允许实现：

- UI图/原型图/Figma 中已有对应页面、区域、组件或入口。
- 需求只是补充UI图已有组件的文案、数据、字段或状态。
- UI图中存在明确预留区域，且需求内容与区域用途一致。
- 当前轮用户明确要求按需求补充该内容。

不得直接实现：

- UI图没有对应页面、区域或入口的需求。
- 会新增大卡片、大图表、大表格、大弹窗、新页面或工具栏的需求。
- 会改变UI图布局、模块数量或信息密度的需求。
- 会覆盖当前轮用户指令或历史有效用户规则的需求。
- 描述过宽泛、只能推测实现方式的需求。

未映射需求必须记录到 `analysis/requirement-prototype-alignment.md`，最终回复中说明暂不实现。

注意：这里的“未映射需求不得实现”只适用于需求文档内容，不适用于 Figma 链接、Figma Frame、UI图/原型图或状态图。Figma 已提供的页面或状态即使没有需求文档说明，也必须进入页面生成或状态实现计划。

## 页面结构分析

每个需要实现的页面必须产出 `analysis/pages/<page-id>.md`，记录：

- 页面名称、页面类型、目标尺寸、UI图来源和对应模板。
- 顶部、左侧、中央、右侧、底部、弹窗/抽屉区域的位置、尺寸和内容。
- 核心组件、数据、交互、资产和是否必须还原。
- 已映射需求、未映射需求和不得进入本页面的需求。
