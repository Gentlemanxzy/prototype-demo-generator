# 输入材料理解规范

本文件用于指导 Agent 如何理解产品经理提供的需求文档、原型图、页面截图和补充说明。

## 输入类型

常见输入包括：

- 需求说明文档。
- Figma 链接、Figma 节点链接、Figma 源文件或 Figma 导出包。
- `figma-links.txt`、`figma-links.md`、`figma-links.csv` 或其他 Figma 链接清单。
- 原型图截图。
- Figma 导出图。
- 页面手绘图。
- 背景图、地图、厂区鸟瞰图或三维模型图。
- logo、图标、装饰线条和设备素材。
- 竞品截图。
- 用户口头描述。
- 业务流程说明。
- 数据字段表。
- 客户演示提纲。

## 原型图片优先规则

当用户上传 PNG、JPG、WebP、Figma 截图或页面截图时，必须把这些图片作为最高优先级输入。

Agent 必须：

1. 逐张分析图片。
2. 判断每张图片对应的页面名称和页面类型。
3. 识别画布比例和主要安全区。
4. 拆解顶部、左侧、中央、右侧、底部和弹窗等区域。
5. 识别组件数量、组件位置、尺寸比例和信息层级。
6. 识别背景图、logo、图标、装饰元素、地图素材和设备素材。
7. 识别颜色、透明度、字号层级、边框、阴影和发光效果。
8. 识别页面中的点击、hover、弹窗、筛选、跳转和联动关系。
9. 按 `references/prototype-analysis.md` 形成页面分析结论。
10. 按 `references/visual-detail-analysis.md` 形成逐页视觉细节分析。

不要只把原型图作为“风格参考”。原型图应直接决定页面结构和视觉比例。

如果原型图与设计规范存在冲突，以原型图为准。设计规范只用于补充原型图未体现或无法判断的细节，不得覆盖原型中的颜色、透明度、面板层级、字号、间距、阴影、发光和组件形态。

## Figma 输入优先规则

当用户提供 Figma 链接、Figma 节点链接、Figma 源文件或 Figma 导出包时，必须优先按 `references/figma-input.md` 提取页面结构、图层、尺寸、颜色、透明度、描边、阴影、模糊、字号和资产。

当用户提供 Figma 链接清单文件时，必须先读取清单文件，提取所有 Figma URL，产出 `analysis/figma-link-map.md`，再逐条建立 `analysis/prototype-page-map.md`。不得只处理第一条链接或忽略无页面名的链接。

Figma 数据优先于截图估算。截图用于对照整体视觉效果；如果 Figma 数据与截图观感存在轻微差异，应优先保持 Figma 的结构和样式，再通过截图验收微调。

如果只能读取 Figma 导出图，无法读取源结构，则按原型图片优先规则处理，并在最终回复中说明无法直接读取 Figma 图层数据。

## 原型页面映射要求

当原型目录包含多张图片时，必须先产出 `analysis/prototype-page-map.md`。

页面映射必须区分：

- 主页面：例如场景总览、运行监测、水质监测、水量监测、设备管理。
- 交互状态：例如展开态、选中态、弹窗态、详情态、轨迹查看态。
- 共享结构：例如顶部导航、左侧菜单、右侧场景目录、底部状态栏。
- 可暂缓状态：暂不实现时必须说明原因。

不要只挑选前三张原型图实现。除非用户明确限定页面范围，否则所有原型图都要被登记和处理。

## 需求提取内容

Agent 应从输入材料中提取以下信息：

- 项目名称。
- 使用对象。
- 水厂类型。
- 页面清单。
- 导航结构。
- 核心业务流程。
- 核心指标。
- 图表需求。
- 表格字段。
- 设备类型。
- 告警类型。
- 演示重点。

如果同时提供需求文档和原型图、Figma 链接、Figma Frame 或页面截图，必须按 `references/requirement-prototype-alignment.md` 产出 `analysis/requirement-prototype-alignment.md`。需求内容只有能对应到原型页面、区域、组件或交互时才允许实现；无法对应的需求必须登记为未映射需求，不得自由新增模块承载。

## 页面识别规则

如果原型图包含多个页面，应识别：

- 页面标题。
- 页面层级。
- 顶部导航或侧边导航。
- 页面主内容区。
- 筛选条件。
- 操作按钮。
- 数据卡片。
- 图表区域。
- 表格区域。
- 地图或厂区场景区域。
- 弹窗、抽屉或详情页。

每张原型图应尽量对应一个页面，避免把多张原型图混合成一个泛化页面。

## 资产识别规则

优先读取用户单独提供的资产包或素材目录。只有当用户没有单独提供资产时，才从原型图中识别可复用视觉内容。

如果输入中出现视觉资产，应记录：

- 资产文件名或来源。
- 资产类型。
- 资产在原型中的位置。
- 是否必须复用。
- 可否裁切、缩放或加遮罩。

背景图、地图、厂区鸟瞰图、三维模型图、logo 和关键图标应优先复用，不应随意改用 CSS 背景。

如果只有原型截图、没有独立资产，应记录：

- 哪些视觉内容可以用原型截图裁切或整图作为背景。
- 哪些图标和装饰只能用近似方式复刻。
- 哪些差异需要在最终回复中说明。

## 信息缺失时的默认补全

如果用户没有给出完整页面，默认生成以下水厂演示页面：

- 场景总览。
- 运行监测。
- 水质监测。

如果用户没有给出具体数据，使用水厂行业合理 Mock 数据。

如果没有原型图，可根据水厂页面级模板和设计规范生成完整演示系统，但最终回复中应说明这是“基于模板生成”，不是高保真原型还原。

## 需要向用户确认的情况

只有出现以下情况时才提问：

- 无法判断是供水厂还是污水厂。
- 用户明确要求完全还原某个原型，但原型图缺失。
- 用户要求接入真实系统或真实接口。
- 页面数量、交付方式或技术栈存在冲突。
- 多张原型图之间存在明显矛盾，且无法合理判断优先级。
