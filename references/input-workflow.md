# 输入与页面拆分工作流

本文件统一约束用户指令、Figma/UI 图、需求文档、页面范围、需求映射和资产识别。公司 UI 视觉规范放在 `design-spec.md`，不要在本文档重复。

## 1. 用户指令

用户文本指令是最高优先级输入，包括生成前说明、生成中反馈和生成后的多轮修改。

必须产出或更新 `analysis/user-instructions.md`：

- 当前轮用户明确要求。
- 历史仍有效规则。
- 被当前轮覆盖的旧规则。
- 与 Figma/UI 图、需求文档或模板冲突时的取舍。
- 本轮只影响哪些页面、组件、样式、数据或交互。

多轮修改必须在现有项目上增量完成，不要无故重建整套页面。

## 2. 输入材料识别

支持以下输入：

- 用户文本、补充生成要求、修改意见。
- 需求文档、需求压缩包和已解压 Markdown/Word 文档。
- Figma 单页面链接、Figma 节点链接、`.fig` 文件、Figma 导出包。
- `figma-links.txt`、`figma-links.md`、`figma-links.csv`。
- UI 图/原型图/页面截图/Figma 导出图。
- 背景图、底图、地图、鸟瞰图、三维模型图、logo、图标、装饰线和设备素材。

读取中文文件时必须使用 UTF-8。

## 3. Figma 链接清单

如果提供 Figma 链接清单，必须读取所有有效链接，不得只处理第一条。

支持格式示例：

```text
A1-场景总览:https://www.figma.com/design/xxx?node-id=25429-7480&m=dev
A2-运行监测:https://www.figma.com/design/xxx?node-id=25429-7658&m=dev
```

必须产出 `analysis/figma-link-map.md`，记录：

- 原始行内容。
- 页面编号和页面名称。
- Figma URL。
- node-id。
- 解析状态：已解析、无法访问、需用户授权、用 UI 图替代。
- 与主页面、子页面、弹窗、展开态、选中态或切换态的关系。

如果无法直接访问或解析 Figma，应记录限制，并优先使用已上传 UI 图、需求文档和底图继续生成。

## 4. 页面范围

Figma 链接、Frame、UI 图、截图和状态图本身就是页面或交互状态的生成依据，不需要先在需求文档中找到对应条目。

必须产出 `analysis/page-scope.md`：

- 主页面列表。
- 子页面列表。
- 弹窗、抽屉、展开态、详情态、选中态、轨迹态、切换态列表。
- 每个状态的父页面和触发入口假设。
- 已生成、暂缓、无法判断的页面或状态。

规则：

- 多个 Figma 链接、多个 UI 图、多个页面编号或多个需求文档不得合并成一个单页面 Demo。
- 没有需求文档说明的 Figma 页面或 UI 图也必须生成，或作为状态挂到父页面。
- 同一模块下多个 Figma 链接通常表示弹出层、展开态、详情态、子页面或切换状态。
- 无法判断触发入口时，按页面命名、可见入口和业务常识做轻量假设，并记录在分析文件和最终回复中。

## 5. UI 图页面映射

必须产出 `analysis/prototype-page-map.md`，记录每张 UI 图、原型图、Figma Frame 与页面/状态的对应关系：

- 文件名或 Figma 节点。
- 页面编号。
- 页面名称。
- 页面类型：主页面、弹窗、展开态、选中态、详情态、轨迹态、子页面。
- 父页面。
- 触发入口。
- 实现方式：独立路由、视图切换、弹窗、抽屉、局部状态。

## 6. 需求文档映射

需求文档主要用于补充：

- 操作逻辑。
- 数据要求。
- 指标含义。
- 字段口径。
- 单位、阈值和状态规则。
- 演示重点。

需求文档不得默认决定：

- 页面布局。
- 模块数量。
- 视觉样式。
- 背景构图。
- 字体层级。
- 面板位置。
- 点位坐标。
- 新增页面或合并页面。

必须产出 `analysis/requirement-prototype-alignment.md`：

- 需求条目。
- 来源文档。
- 映射到的 UI 页面、区域、组件或交互。
- 是否实现。
- 未映射原因。

未映射需求不得自由发挥到界面中。

## 7. 逐页分析

每个页面或状态必须产出：

- `analysis/pages/<page-id>.md`：布局、区域、组件、资产、数据和交互。
- `analysis/pages/<page-id>-visual-details.md`：背景、遮罩、透明度、描边、阴影、发光、圆角、点位、字体和状态样式。

当页面包含文字时，必须产出 `analysis/typography-scale.md`。

当页面包含图表时，必须产出 `analysis/chart-spec.md`。

当页面包含导航、菜单、标签、详情、弹窗、筛选或切换时，必须产出 `analysis/interaction-logic.md`。

## 8. 资产识别

必须产出 `analysis/assets-inventory.md`，记录：

- 背景图、底图、地图、鸟瞰图、三维模型图。
- logo、图标、装饰线、设备图片。
- 来源：Figma、用户素材、UI 图裁切、模板兜底。
- 使用页面和使用位置。
- 是否已复制到输出目录。

资产优先级：

1. Figma 中提取或导出的真实图片、logo、图标和装饰资产。
2. 用户单独提供的素材目录或资产包。
3. 用户明确指定可复用的背景图、logo、图标和截图。
4. UI 图/原型图中可识别、可裁切或可近似复刻的视觉内容。
5. 页面模板或设计规范中的默认视觉方案。

如果用户单独提供背景图、logo、图标等资产，优先使用用户资产；未提供时再从 UI 图中识别或近似复刻。

## 9. 页面模板使用

页面模板只补充业务内容，不得改变 UI 图布局、模块数量和视觉层级。

当 UI 图信息不足时，根据页面名称读取 `templates/water-plant/` 下对应模板补充业务字段、指标和交互建议。
