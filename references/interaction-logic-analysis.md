# 操作逻辑分析规范

本文件用于指导 Agent 在写代码前拆解需求文档和原型图中的操作逻辑，避免页面只有视觉雏形、没有可演示的业务交互。

当输入包含需求文档、原型图、Figma 设计或页面状态图时，必须产出：

- `analysis/interaction-logic.md`

## 分析原则

- 原型图决定可点击元素的位置、样式和状态。
- 需求文档决定业务流程、菜单含义、页面切换和数据口径。
- 需求文档中的操作逻辑必须先映射到原型中的入口、区域、组件或状态；无法映射的逻辑不得直接实现。
- 页面模板只用于补充已映射区域内缺失的业务逻辑，不得覆盖原型和需求。
- 如果真实指标无法从原型图或需求文档提取，可以补充模拟指标，但必须标注“模拟数据”或“Mock 数据”。

## 顶部导航

必须登记：

- 导航项名称。
- 对应页面或视图。
- 默认选中项。
- hover 样式。
- 选中态样式。
- 点击后的切换行为。
- 是否更新页面标题、左侧菜单、中央主视觉和右侧内容。
- 来源是否已登记到 `analysis/requirement-prototype-alignment.md`。

顶部导航不是装饰元素。除非用户明确要求静态截图页，否则顶部导航必须支持可演示的页面切换或视图切换。

顶部导航的字体样式必须来自原型图或 Figma：包括字体家族、字号、字重、颜色、行高、间距和选中态文字样式。禁止使用通用大屏默认导航字体替代原型。

## 左侧业务菜单

必须登记：

- 菜单项名称。
- 当前页面下的选中态。
- 点击行为。
- 是否联动中央主视觉和右侧详情。

如果原型图或需求文档没有出现三维工具栏，不得新增“主视角、空间剖切、测量、气候调整、时间回溯”等通用工具按钮。

## 底图标签和点位

每个标签必须登记：

- 唯一 ID。
- 显示名称。
- 原型坐标或相对百分比。
- 所属页面。
- 所属区域或设备。
- hover 样式。
- 选中态样式。
- 点击后的详情标题。
- 点击后的指标列表。
- 点击后的图表或状态列表。
- 数据来源：需求文档、Figma/原型、模拟数据。

禁止多个标签点击后都显示同一个详情内容。即使使用模拟数据，不同标签也必须展示不同标题、不同指标和不同状态。

## 右侧详情和弹窗

必须登记：

- 触发来源。
- 标题。
- 展示字段。
- 指标数量。
- 列表或图表内容。
- 是否显示模拟数据标注。
- 关闭或返回方式。
