# 输出规范

本文件用于约束 Agent 生成的前端演示系统。

## 默认输出形式

默认生成一套可本地运行的前端项目。

推荐结构：

- 登录页或入口页。
- 主布局。
- 顶部导航栏或平台顶栏。
- 页面路由。
- 模拟数据。
- 可复用业务组件。
- 图表组件。
- 水厂主题样式。
- `analysis/user-instructions.md`。
- `analysis/figma-link-map.md`。
- `analysis/prototype-page-map.md`。
- `analysis/page-scope.md`。
- `analysis/requirement-prototype-alignment.md`。
- `analysis/assets-inventory.md`。
- `analysis/pages/*.md`。
- `analysis/pages/*-visual-details.md`。
- `analysis/typography-scale.md`。
- `analysis/chart-spec.md`。
- `analysis/interaction-logic.md`。
- `analysis/responsive-adaptation.md`。
- `analysis/visual-check-report.md`。

## 预览入口要求

最终交付必须保证用户最容易点击的根入口可预览：

- `workspace/index.html` 必须能直接打开并看到页面。
- 如果使用纯静态 HTML/CSS/JS，根入口就是最终页面。
- 如果使用 Vue/Vite，必须完成 `npm run build`，并让 `workspace/index.html` 加载构建后的 `dist/assets`、跳转到 `dist/index.html`，或把构建产物同步到根入口。
- Vue/Vite 的根入口不得只包含 `<script type="module" src="/src/main.js"></script>` 这类开发服务器路径。
- Vite 配置必须使用相对资源路径，例如 `base: "./"`，保证构建产物通过静态服务和本地路径都能加载资源。
- 最终回复和 `generation-summary.md` 必须明确写出首选预览入口；如果同时存在源码入口和构建入口，必须说明用户应打开哪一个。

## Vue/Vite 输出要求

当用户指定 Vue 架构或默认选择 Vue/Vite 时，优先生成轻量、稳定、可构建的 Vue 项目：

- 首版推荐 `Vue 3 + Vite + ECharts + CSS`。
- 默认使用 JavaScript：`src/main.js`、`src/App.vue`、`vite.config.js`。
- 只有用户明确要求 TypeScript 时，才使用 `src/main.ts`、`tsconfig.json` 和 `vue-tsc`。
- 只有用户明确要求或现有项目需要时，才引入 Tailwind CSS、Element Plus、Three.js、状态管理库或 Vue Router。
- 多主页面可以用 Vue 组件和菜单状态切换实现；只有页面 URL、浏览器前进后退或真实路由是明确要求时，才引入 Vue Router。
- `vite.config.js` / `vite.config.ts` 必须包含：

```js
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";

export default defineConfig({
  base: "./",
  plugins: [vue()],
});
```

- `package.json` 的 `build` 脚本首选 `vite build`。只有 TypeScript 严格校验是用户明确要求时，才使用 `vue-tsc -b && vite build`。
- 构建失败时必须先修复 Vite/Vue 配置、导入路径和依赖版本，再继续截图验收。

如果输入包含用户文本指令，输出必须先依据 `references/user-instructions.md` 更新 `analysis/user-instructions.md`，并以当前轮明确指令为最高优先级。

如果输入包含UI图/原型图，输出应以“还原UI页面”为核心，而不是重新设计同主题页面。

如果输入包含 Figma 链接、Figma 节点链接、Figma 源文件或 Figma 导出包，输出应优先依据 `references/input-analysis.md` 和 `references/assets-and-figma.md` 形成的分析结果实现。

如果输入包含 Figma 链接清单文件，必须输出 `analysis/figma-link-map.md`，并确保清单中所有有效链接已登记到 `analysis/prototype-page-map.md`。

Figma 链接、Frame、UI图/原型图和状态图是页面或状态的直接生成依据。不得因为缺少需求文档对应说明而跳过 Figma 已提供的页面、弹窗、抽屉、展开态、选中态、详情态、子页面或切换态。

如果用户提交了多个 Figma 链接、多个 UI 图、多个需求文档、多个页面编号或多个模块，输出不得默认只有一个页面。必须先根据 `analysis/page-scope.md` 判断页面范围，再生成多页面演示系统。

多页面输出要求：

- 多个主页面必须具备可访问入口，例如 Vue Router、顶部导航、左侧菜单、tab 切换或静态 HTML 中的视图切换。
- 子页面、弹窗、抽屉、展开态、详情态必须挂在对应父页面下，由明确入口触发。
- 页面切换时必须同步顶部导航或左侧菜单选中态。
- 首页只能作为默认入口，不得替代其他已提交页面。
- 最终回复和 `generation-summary.md` 必须列出已生成主页面、子页面、状态页和暂缓页面。

## 高保真输出要求

生成页面必须：

- 保持顶部导航栏或平台顶栏；除非UI图/原型图明确没有顶部栏，否则不得省略。
- 保持UI图布局。
- 保持模块数量。
- 保持主要视觉比例。
- 保持背景构图。
- 保持颜色关系。
- 保持面板透明度和层级。
- 保持背景遮罩、面板底色、透明度、边框、阴影、发光和标题栏分层。
- 保持信息密度。
- 保持字号层级。
- 保持主要交互状态。
- 保持需求文档中已经映射到UI图承载区域的主要操作逻辑。
- 保持当前轮用户明确要求的修改点和限制条件。

禁止：

- 自己重新设计首页。
- 添加UI图中不存在的大卡片。
- 删除UI图中的主要模块。
- 合并多个UI页面。
- 把多个 Figma 链接、UI 图、需求文档或页面编号合并成一个单页面 Demo。
- 跳过没有需求文档对应说明的 Figma 页面或状态图。
- 忽略展开态、选中态、弹窗态、轨迹态等状态 UI 图。
- 使用通用后台布局替代UI图布局。
- 使用纯 CSS 背景替代用户提供的关键视觉资产。
- 用统一通用 GlassPanel 样式替代UI图中不同层级的面板、弹窗、标签和图表容器。
- 使用通用字体、默认字号或过大的 KPI 字号替代UI图中的顶部导航、右侧卡片、标签和指标文字。
- 未建立 `analysis/typography-scale.md` 就直接写主要页面字体样式。
- 新增UI图/原型图和需求文档中未出现的通用三维工具栏，例如主视角、空间剖切、测量、气候调整、时间回溯等。
- 把需求文档中无法对应到UI页面、区域、组件或交互的内容自由发挥成新模块。
- 让需求文档覆盖当前轮用户指令或 Figma/UI图布局视觉。

## 用户指令和多轮改进要求

当用户在生成前、生成中或生成后提供文本指令时，必须：

- 产出或更新 `analysis/user-instructions.md`。
- 当前轮明确指令优先于历史规则、Figma/UI图、需求文档、模板和设计规范。
- 历史有效规则优先于 Figma/UI图、需求文档、模板和设计规范。
- 如果当前轮指令覆盖旧规则、Figma 或需求文档，必须在 `analysis/user-instructions.md` 和最终回复中说明。
- 多轮修改时优先在现有项目上增量修改，不要无故重建整套页面。
- 多轮修改后只改变受影响页面、组件、样式、数据或交互，保留未受影响的已完成效果。

用户指令示例：

- 删除或保留某个模块。
- 指定某个页面、截图、Figma 节点为准。
- 要求某个交互必须可用。
- 要求某类数据使用合理演示数据。
- 要求某个旧规则作废。

## 大屏画布要求

如果输出为水厂数字孪生大屏，应采用 `1920 × 1080` 固定业务画布，除非UI图/原型图本身是其他比例。

实现要求：

- 页面必须填满浏览器视口，不允许四周出现黑边。
- 默认使用 cover 缩放策略：在保持业务画布比例的前提下填满屏幕，允许边缘轻微裁切。
- 核心导航、菜单、指标、面板、弹窗、图表和操作区域必须放在安全区内，不能被 cover 裁切影响演示。
- 业务画布居中显示并保持UI图/原型图中的空间关系。
- 核心模块不因窗口尺寸变化而重新排列。
- 保留合理安全边距。
- 面板内边距优先使用 `16px / 24px`。
- 所有间距尽量遵循 8px 网格。
- 必须按 `references/implementation-rules.md` 产出 `analysis/responsive-adaptation.md`，并检查 `1920×1080`、`1440×900`、`1366×768` 和当前浏览器窗口。
- 页面不能只在 `1920×1080` 正常；普通浏览器窗口下也不得出现明显上、左、右黑边。

## 页面还原要求

当输入包含UI图/原型图或页面截图时，输出页面应优先高保真还原UI图/原型图。

- 按UI图/原型图分别生成对应页面，不要把多个页面合并成一个泛化页面。
- `figma-links.txt` 或 Figma 链接清单中的所有有效链接都必须生成或登记为状态实现；同一模块下多个链接应识别为主页面、弹出层、展开态、子页面或切换态关系。
- 如果 `analysis/page-scope.md` 中存在多个主页面，必须为每个主页面生成独立页面、路由或可切换视图。
- 如果 `analysis/page-scope.md` 中存在子页面或状态页，必须在父页面中实现触发入口；无法判断触发入口时必须在分析文件和最终回复中说明假设。
- 保持UI图/原型图中的顶部导航、左侧菜单、右侧面板、底部状态栏、中央主视觉、地图标注点、弹窗和图表区域的位置关系。
- 保持UI图/原型图的背景图构图、遮罩强度、毛玻璃透明度、字号层级、文字密度和信息层级。
- 保持UI图/原型图中的底图标签、地图点位、设备热点或工艺节点坐标；使用 cover 缩放时必须校准点位偏移。
- 不随意新增、删除、合并或重排UI图/原型图中的主要模块。
- 需求文档用于补充操作逻辑、数据要求、指标含义、字段口径、单位、阈值和演示重点；当需求文档与用户指令或UI图/原型图布局冲突时，优先保留用户指令和UI图/原型图布局。
- 需求文档中的内容必须先按 `references/input-analysis.md` 映射到UI图承载区域；未映射内容不得进入页面实现。
- 需求文档不得默认决定页面布局、模块数量、视觉样式、背景构图、字体层级、面板位置、点位坐标、页面新增或页面合并。
- 没有需求文档说明的 Figma 页面，也应按 Figma/UI图还原；业务数据可使用合理演示数据，不需要在界面明确标注模拟数据。
- 设计规范用于补充缺失细节；当设计规范与UI图/原型图视觉冲突时，必须以UI图/原型图为准。

## 视觉细节还原要求

当输入包含UI图/原型图或页面截图时，必须先产出 `analysis/pages/<page-id>-visual-details.md`，再实现页面样式。

当页面包含任何文字时，还必须先产出 `analysis/typography-scale.md`。字体大小、行高、字重和文字密度必须优先按 Figma/UI图采样或估算，`references/design-spec.md` 的字号层级只作为缺省兜底，不得覆盖UI图中更小、更紧凑的字号。

必须还原或近似还原：

- 背景图亮度、遮罩颜色、遮罩透明度和渐变压暗。
- 顶部导航、左侧菜单、左右面板、底部栏、弹窗、标签和图表容器的不同透明度。
- 面板标题栏和内容区的分层。
- 描边颜色、描边透明度、渐变描边、内阴影、外阴影和发光强度。
- 角标、装饰线、分割线、折角、选中线等局部细节。
- 页面标题、面板标题、指标数字、单位、列表、表格和辅助文字的字号层级。
- 顶部导航、右侧卡片、底图标签和指标数值的真实字体样式；如果无法精准获取，应采用接近 UI 图的偏小、紧凑字号，而不是默认大屏夸张字号。
- 列表行高、面板内边距、模块间距和信息密度。

字体实现要求：

- CSS 中应集中定义页面字体 token 或变量，并与 `analysis/typography-scale.md` 对应。
- 普通文本、导航、表格、列表、卡片标题和图表坐标轴不得默认超过 `14-16px`。
- 右侧卡片数值默认不得超过 `24px`，除非UI图明确是大数字。
- 核心大 KPI 默认不得超过 `32px`，且只能用于UI图中明确突出的大数字。
- 非 1920 视口下应整体缩放业务画布，不得单独放大字体。
- 文字过大导致换行、遮挡、卡片挤压或信息密度下降时，必须优先缩小字号、行高和间距。

禁止使用以下默认写法作为主要字号体系：

```css
.title { font-size: 32px; }
.panel-title { font-size: 20px; }
.kpi-value { font-size: 36px; }
.nav-item { font-size: 18px; }
```

禁止只定义一个 `.glass-panel` 后套用到所有区域。不同区域在UI图中透明度、边框、阴影或标题栏不同，就必须拆成不同样式。

## 资产复用要求

用户提供的视觉资产应优先复用：

- 背景图片。
- 厂区鸟瞰图。
- 地图。
- 水厂三维模型图。
- logo。
- 图标。
- 设备图片。
- 装饰元素。

允许对资产进行裁切、缩放、加遮罩、压暗或叠加热区，但不应无理由替换为通用图形。

资产优先级：

1. Figma 中提取或导出的真实图片、logo、图标和装饰资产。
2. 用户单独提供的素材目录或资产包。
3. 用户明确指定可复用的背景图、logo、图标和截图。
4. UI图/原型图中可识别、可裁切或可近似复刻的视觉内容。
5. 页面模板或设计规范中的默认视觉方案。

如果没有独立资产，只能从UI图/原型图近似复刻，必须在 `analysis/assets-inventory.md` 和最终回复中说明。

## 页面要求

每个页面都应具备：

- 顶部导航栏或平台顶栏。
- 清晰标题。
- 页面级筛选或时间范围。
- 关键指标。
- 至少一个主要业务区域。
- 至少一个辅助分析区域。
- 与水厂业务相关的数据或状态。

如果UI图/原型图缺少某些业务内容，可以根据需求文档和页面模板补全；补全部分应贴近UI图风格，不破坏布局。

## 顶部导航要求

除非UI图/原型图明确没有顶部导航栏，否则所有水厂业务页面必须包含顶部导航栏或平台顶栏。

顶部导航栏应包含：

- 平台名称或项目名称。
- 一级模块导航。
- 当前页面选中态。
- 时间或数据刷新状态。
- 用户、天气、系统状态或演示状态信息。

实现要求：

- 顶部导航栏通常位于业务画布 `x=0 y=0`，高度优先参考UI图；没有UI图时默认 `64px`。
- 顶部导航栏字体必须优先按UI图/原型图或 Figma 采样，包括字体家族、字号、字重、行高、颜色、字间距和选中态样式；禁止使用通用默认导航字体替代。
- 顶部导航栏不得被背景图、中央场景、canvas、地图、图表或全屏容器遮挡。
- 左右面板和中央主视觉应从顶栏下方开始布局，或按UI图/原型图保留明确层级。
- 多页面项目切换页面时，顶部导航栏应持续存在，并同步当前页面选中态。
- 顶部导航栏必须支持点击切换页面或视图，并更新当前选中态；不得只做静态装饰。
- 如果UI图/原型图顶部仅是标题栏而不是完整导航，也应还原为平台顶栏，不要完全删除。

## 操作逻辑要求

当输入包含需求文档、UI图/原型图、Figma 设计或页面状态图时，必须按 `references/implementation-rules.md` 产出 `analysis/interaction-logic.md`。

实现要求：

- 顶部导航、左侧业务菜单、底图标签、右侧详情、弹窗、筛选和列表行等主要操作必须有可演示反馈。
- 所有来自需求文档的操作逻辑必须已在 `analysis/requirement-prototype-alignment.md` 中映射到UI页面、区域或组件。
- 点击不同底图标签时，右侧详情标题、指标、图表或状态内容必须发生对应变化。
- 禁止多个不同标签都显示同一个默认详情。
- UI图或需求中没有出现的功能不要自行新增。
- 如果业务指标无法从图片或需求中提取，可以补充合理演示指标，不强制在界面明确标注“模拟数据”或“Mock 数据”。
- 当 Figma 提供弹窗、抽屉、展开态、详情页或子页面切换态，但需求文档没有交互说明时，应根据可见入口、页面命名和状态关系实现轻量切换；无法判断入口时，必须在分析文件和最终回复中说明假设，而不是跳过该状态。

## 图表输出要求

当页面包含折线图、柱状图、面积图、饼图、环图或组合图时，必须先按 `references/implementation-rules.md` 产出 `analysis/chart-spec.md`。

实现要求：

- 优先使用 ECharts 实现真实图表；已有项目使用其他图表库时，可沿用现有图表库，但必须具备真实坐标轴、tooltip 和数据更新能力。
- 折线图、柱状图、面积图和组合图必须显示横坐标、纵坐标、单位、刻度和网格线；除非UI图和需求都明确没有坐标轴。
- 横坐标含义和纵坐标含义只要在 Figma 或需求文档中出现，就必须进入图表配置和界面展示。
- 图表指标切换、时间范围切换和筛选项必须可点击，并更新图表数据、当前选中态和 tooltip 内容。
- ECharts 默认不显示图例。只有 Figma/UI图、需求文档或用户指令明确出现图例、多系列对比说明、图例切换入口时，才允许显示图例。
- 模拟数据只能替代真实数值，不得替代图表含义；不得因为使用模拟数据而删除坐标轴、单位或切换功能；不强制在图表界面明确标注模拟数据。
- 图表容器样式、字号、坐标轴颜色和标签密度应贴近 Figma/UI图，不得使用默认 ECharts 亮色主题。
- 图表空间不足时，应缩小坐标轴字号、减少刻度数量、使用省略或调整 `grid` 内边距，不得直接删除坐标轴。

禁止：

- 用 CSS 线条、静态 SVG、图片或装饰性假图表替代有业务含义的图表。
- 图表只有曲线/柱子但没有横纵坐标含义。
- 指标切换按钮只改变选中样式，不改变图表数据或系列。
- 多个不同指标切换后仍显示同一组默认数据。

## 点位坐标要求

当页面包含底图标签、地图点位、设备热点或工艺节点时，必须按 `references/implementation-rules.md` 记录并校准坐标。

实现要求：

- 记录UI图坐标、UI图尺寸和相对百分比。
- 根据背景图实际显示方式计算最终坐标。
- 使用 cover 缩放时，必须考虑背景图水平或垂直裁切偏移。
- 不得让标签点位整体上移、下移或左右偏移。

## 右侧卡片字体和密度要求

右侧卡片应优先还原UI图/原型图或 Figma 中的字体，不要使用默认大屏卡片字号。

实现要求：

- 卡片标题、指标名称、指标数值、单位、状态标签和说明文字都必须按 UI 图采样或估算。
- 无法精准判断时，右侧卡片标题和数值应使用偏小的紧凑字号，保证内容能在卡片内展示。
- 标题和数值不应因为字号过大导致换行、溢出或挤压图表。
- 长标题、长单位和长说明优先使用省略号、减少模拟字段或缩小字号，不要撑破卡片。
- 指标项应采用“指标名行 + 数值单位行”：指标名可以单独一行，数值和单位必须同一行展示。
- 数值和单位不得作为三个平级元素直接放在 `.metric` 下；必须增加 `.metric-value-row` / `.data-value-row` 包裹数值和单位。
- 数值单位行必须设置 `display: inline-flex` 或 `display: flex`、`align-items: baseline`、`white-space: nowrap`，数值与单位都不得换行。
- 如果卡片宽度不足，优先缩小字号、减少字段、缩短单位或调整间距，不得让单位掉到下一行。

## 视觉实现要求

水厂大屏应引用 `references/design-spec.md` 中的设计规范，并至少实现以下视觉特征：

- 极暗背景 `#050B14`。
- 蓝色主品牌色 `#006AFF`。
- 全息青高亮色 `#7BE8EF`。
- 半透明毛玻璃面板。
- 深色底图遮罩。
- 状态色区分正常、提示、预警和告警。
- 关键数字使用更高字号并保证强对比。

默认 CSS token 应与设计规范保持一致，避免在页面中随意新增冲突色值。

如果UI图/原型图已经体现明确视觉细节，优先按UI图/原型图取样或估算，不强制套用设计规范 token。设计规范仅作为缺省值。

## 交互要求

根据复杂度，优先实现以下交互：

- 菜单切换。
- 时间范围切换。
- 告警筛选。
- 设备状态筛选。
- 表格行点击查看详情。
- 图表随筛选变化。
- 弹窗或侧边详情面板。
- 场景标签 hover 高亮。
- 点击构筑物、设备或告警点位后进入下沉详情。
- 点击告警行后联动定位到对应区域。
- 支持从下沉视图返回总览。

交互样式应与UI图/原型图一致。UI图/原型图未体现的交互，可以采用轻量实现，不应打乱页面结构。

## 数据要求

模拟数据应满足：

- 数值范围合理。
- 状态分布可信。
- 时间趋势有变化。
- 告警内容具体。
- 设备名称贴近水厂场景。

## 文案要求

默认使用中文文案。文案应简洁、专业，避免空泛表达。

示例：

- 今日处理水量。
- 出水 COD。
- 氨氮浓度。
- 进水泵房。
- 二沉池液位。
- 加药间运行状态。
- 高压配电室温度异常。

## 禁止事项

- 不生成只有装饰、没有业务内容的页面。
- 不把需求文档中无法对应UI图的内容自由发挥成页面模块。
- 不使用大量无意义发光边框。
- 不把所有模块都做成一样的卡片。
- 不使用与水厂无关的指标。
- 不在界面中写“这里是图表”“待接入数据”等演示破绽。
