# 输出规范

本文件用于约束 Agent 生成的前端演示系统。

## 默认输出形式

默认生成一套可本地运行的前端项目。

推荐结构：

- 登录页或入口页。
- 主布局。
- 顶部导航栏或平台顶栏。
- 页面路由。
- 模拟数据。
- 可复用业务组件。
- 图表组件。
- 水厂主题样式。
- `analysis/figma-link-map.md`。
- `analysis/prototype-page-map.md`。
- `analysis/requirement-prototype-alignment.md`。
- `analysis/assets-inventory.md`。
- `analysis/pages/*.md`。
- `analysis/pages/*-visual-details.md`。
- `analysis/interaction-logic.md`。
- `analysis/responsive-adaptation.md`。
- `analysis/visual-check-report.md`。

如果输入包含原型图，输出应以“还原原型页面”为核心，而不是重新设计同主题页面。

如果输入包含 Figma 链接、Figma 节点链接、Figma 源文件或 Figma 导出包，输出应优先依据 `references/figma-input.md` 形成的分析结果实现。

如果输入包含 Figma 链接清单文件，必须输出 `analysis/figma-link-map.md`，并确保清单中所有有效链接已登记到 `analysis/prototype-page-map.md`。

## 高保真输出要求

生成页面必须：

- 保持顶部导航栏或平台顶栏；除非原型图明确没有顶部栏，否则不得省略。
- 保持原型布局。
- 保持模块数量。
- 保持主要视觉比例。
- 保持背景构图。
- 保持颜色关系。
- 保持面板透明度和层级。
- 保持背景遮罩、面板底色、透明度、边框、阴影、发光和标题栏分层。
- 保持信息密度。
- 保持字号层级。
- 保持主要交互状态。
- 保持需求文档中已经映射到原型承载区域的主要操作逻辑。

禁止：

- 自己重新设计首页。
- 添加原型中不存在的大卡片。
- 删除原型中的主要模块。
- 合并多个原型页面。
- 忽略展开态、选中态、弹窗态、轨迹态等状态原型。
- 使用通用后台布局替代原型布局。
- 使用纯 CSS 背景替代用户提供的关键视觉资产。
- 用统一通用 GlassPanel 样式替代原型中不同层级的面板、弹窗、标签和图表容器。
- 使用通用字体、默认字号或过大的 KPI 字号替代原型中的顶部导航、右侧卡片、标签和指标文字。
- 新增原型图和需求文档中未出现的通用三维工具栏，例如主视角、空间剖切、测量、气候调整、时间回溯等。
- 把需求文档中无法对应到原型页面、区域、组件或交互的内容自由发挥成新模块。

## 大屏画布要求

如果输出为水厂数字孪生大屏，应采用 `1920 × 1080` 固定业务画布，除非原型图本身是其他比例。

实现要求：

- 页面必须填满浏览器视口，不允许四周出现黑边。
- 默认使用 cover 缩放策略：在保持业务画布比例的前提下填满屏幕，允许边缘轻微裁切。
- 核心导航、菜单、指标、面板、弹窗、图表和操作区域必须放在安全区内，不能被 cover 裁切影响演示。
- 业务画布居中显示并保持原型图中的空间关系。
- 核心模块不因窗口尺寸变化而重新排列。
- 保留合理安全边距。
- 面板内边距优先使用 `16px / 24px`。
- 所有间距尽量遵循 8px 网格。
- 必须按 `references/responsive-adaptation.md` 产出 `analysis/responsive-adaptation.md`，并检查 `1920×1080`、`1440×900`、`1366×768` 和当前浏览器窗口。
- 页面不能只在 `1920×1080` 正常；普通浏览器窗口下也不得出现明显上、左、右黑边。

## 页面还原要求

当输入包含原型图或页面截图时，输出页面应优先高保真还原原型图。

- 按原型图分别生成对应页面，不要把多个页面合并成一个泛化页面。
- 保持原型图中的顶部导航、左侧菜单、右侧面板、底部状态栏、中央主视觉、地图标注点、弹窗和图表区域的位置关系。
- 保持原型图的背景图构图、遮罩强度、毛玻璃透明度、字号层级、文字密度和信息层级。
- 保持原型图中的底图标签、地图点位、设备热点或工艺节点坐标；使用 cover 缩放时必须校准点位偏移。
- 不随意新增、删除、合并或重排原型图中的主要模块。
- 需求文档用于补充业务文字、指标和交互细节；当需求文档与原型图布局冲突时，优先保留原型图布局。
- 需求文档中的内容必须先按 `references/requirement-prototype-alignment.md` 映射到原型承载区域；未映射内容不得进入页面实现。
- 设计规范用于补充缺失细节；当设计规范与原型图视觉冲突时，必须以原型图为准。

## 视觉细节还原要求

当输入包含原型图或页面截图时，必须先产出 `analysis/pages/<page-id>-visual-details.md`，再实现页面样式。

必须还原或近似还原：

- 背景图亮度、遮罩颜色、遮罩透明度和渐变压暗。
- 顶部导航、左侧菜单、左右面板、底部栏、弹窗、标签和图表容器的不同透明度。
- 面板标题栏和内容区的分层。
- 描边颜色、描边透明度、渐变描边、内阴影、外阴影和发光强度。
- 角标、装饰线、分割线、折角、选中线等局部细节。
- 页面标题、面板标题、指标数字、单位、列表、表格和辅助文字的字号层级。
- 顶部导航、右侧卡片、底图标签和指标数值的真实字体样式；如果无法精准获取，应采用接近原型的偏小、紧凑字号，而不是默认大屏夸张字号。
- 列表行高、面板内边距、模块间距和信息密度。

禁止只定义一个 `.glass-panel` 后套用到所有区域。不同区域在原型中透明度、边框、阴影或标题栏不同，就必须拆成不同样式。

## 资产复用要求

用户提供的视觉资产应优先复用：

- 背景图片。
- 厂区鸟瞰图。
- 地图。
- 水厂三维模型图。
- logo。
- 图标。
- 设备图片。
- 装饰元素。

允许对资产进行裁切、缩放、加遮罩、压暗或叠加热区，但不应无理由替换为通用图形。

资产优先级：

1. Figma 中提取或导出的真实图片、logo、图标和装饰资产。
2. 用户单独提供的素材目录或资产包。
3. 用户明确指定可复用的背景图、logo、图标和截图。
4. 原型图中可识别、可裁切或可近似复刻的视觉内容。
5. 页面模板或设计规范中的默认视觉方案。

如果没有独立资产，只能从原型图近似复刻，必须在 `analysis/assets-inventory.md` 和最终回复中说明。

## 页面要求

每个页面都应具备：

- 顶部导航栏或平台顶栏。
- 清晰标题。
- 页面级筛选或时间范围。
- 关键指标。
- 至少一个主要业务区域。
- 至少一个辅助分析区域。
- 与水厂业务相关的数据或状态。

如果原型图缺少某些业务内容，可以根据需求文档和页面模板补全；补全部分应贴近原型风格，不破坏布局。

## 顶部导航要求

除非原型图明确没有顶部导航栏，否则所有水厂业务页面必须包含顶部导航栏或平台顶栏。

顶部导航栏应包含：

- 平台名称或项目名称。
- 一级模块导航。
- 当前页面选中态。
- 时间或数据刷新状态。
- 用户、天气、系统状态或演示状态信息。

实现要求：

- 顶部导航栏通常位于业务画布 `x=0 y=0`，高度优先参考原型；没有原型时默认 `64px`。
- 顶部导航栏字体必须优先按原型图或 Figma 采样，包括字体家族、字号、字重、行高、颜色、字间距和选中态样式；禁止使用通用默认导航字体替代。
- 顶部导航栏不得被背景图、中央场景、canvas、地图、图表或全屏容器遮挡。
- 左右面板和中央主视觉应从顶栏下方开始布局，或按原型图保留明确层级。
- 多页面项目切换页面时，顶部导航栏应持续存在，并同步当前页面选中态。
- 顶部导航栏必须支持点击切换页面或视图，并更新当前选中态；不得只做静态装饰。
- 如果原型图顶部仅是标题栏而不是完整导航，也应还原为平台顶栏，不要完全删除。

## 操作逻辑要求

当输入包含需求文档、原型图、Figma 设计或页面状态图时，必须按 `references/interaction-logic-analysis.md` 产出 `analysis/interaction-logic.md`。

实现要求：

- 顶部导航、左侧业务菜单、底图标签、右侧详情、弹窗、筛选和列表行等主要操作必须有可演示反馈。
- 所有来自需求文档的操作逻辑必须已在 `analysis/requirement-prototype-alignment.md` 中映射到原型页面、区域或组件。
- 点击不同底图标签时，右侧详情标题、指标、图表或状态内容必须发生对应变化。
- 禁止多个不同标签都显示同一个默认详情。
- 原型或需求中没有出现的功能不要自行新增。
- 如果业务指标无法从图片或需求中提取，可以补充模拟指标，但必须在界面合适位置标注“模拟数据”或“Mock 数据”。

## 点位坐标要求

当页面包含底图标签、地图点位、设备热点或工艺节点时，必须按 `references/responsive-adaptation.md` 记录并校准坐标。

实现要求：

- 记录原型坐标、原型尺寸和相对百分比。
- 根据背景图实际显示方式计算最终坐标。
- 使用 cover 缩放时，必须考虑背景图水平或垂直裁切偏移。
- 不得让标签点位整体上移、下移或左右偏移。

## 右侧卡片字体和密度要求

右侧卡片应优先还原原型图或 Figma 中的字体，不要使用默认大屏卡片字号。

实现要求：

- 卡片标题、指标名称、指标数值、单位、状态标签和说明文字都必须按原型采样或估算。
- 无法精准判断时，右侧卡片标题和数值应使用偏小的紧凑字号，保证内容能在卡片内展示。
- 标题和数值不应因为字号过大导致换行、溢出或挤压图表。
- 长标题、长单位和长说明优先使用省略号、减少模拟字段或缩小字号，不要撑破卡片。

## 视觉实现要求

水厂大屏应引用 `references/design-spec.md` 中的设计规范，并至少实现以下视觉特征：

- 极暗背景 `#050B14`。
- 蓝色主品牌色 `#006AFF`。
- 全息青高亮色 `#7BE8EF`。
- 半透明毛玻璃面板。
- 深色底图遮罩。
- 状态色区分正常、提示、预警和告警。
- 关键数字使用更高字号并保证强对比。

默认 CSS token 应与设计规范保持一致，避免在页面中随意新增冲突色值。

如果原型图已经体现明确视觉细节，优先按原型图取样或估算，不强制套用设计规范 token。设计规范仅作为缺省值。

## 交互要求

根据复杂度，优先实现以下交互：

- 菜单切换。
- 时间范围切换。
- 告警筛选。
- 设备状态筛选。
- 表格行点击查看详情。
- 图表随筛选变化。
- 弹窗或侧边详情面板。
- 场景标签 hover 高亮。
- 点击构筑物、设备或告警点位后进入下沉详情。
- 点击告警行后联动定位到对应区域。
- 支持从下沉视图返回总览。

交互样式应与原型图一致。原型图未体现的交互，可以采用轻量实现，不应打乱页面结构。

## 数据要求

模拟数据应满足：

- 数值范围合理。
- 状态分布可信。
- 时间趋势有变化。
- 告警内容具体。
- 设备名称贴近水厂场景。

## 文案要求

默认使用中文文案。文案应简洁、专业，避免空泛表达。

示例：

- 今日处理水量。
- 出水 COD。
- 氨氮浓度。
- 进水泵房。
- 二沉池液位。
- 加药间运行状态。
- 高压配电室温度异常。

## 禁止事项

- 不生成只有装饰、没有业务内容的页面。
- 不把需求文档中无法对应原型的内容自由发挥成页面模块。
- 不使用大量无意义发光边框。
- 不把所有模块都做成一样的卡片。
- 不使用与水厂无关的指标。
- 不在界面中写“这里是图表”“待接入数据”等演示破绽。
