# 原型分析规范

本文件用于指导 Agent 在写代码前拆解用户提供的原型图、页面截图或 Figma 导出图。

原型分析是必做步骤。不要直接从图片跳到代码实现。

## 分析输出位置

建议在生成项目内输出：

- `analysis/prototype-analysis.md`
- `analysis/prototype-page-map.md`
- `analysis/requirement-prototype-alignment.md`
- `analysis/assets-inventory.md`
- `analysis/pages/<page-id>-visual-details.md`

如果是多页面项目，可按页面拆分：

- `analysis/pages/A1-overview.md`
- `analysis/pages/A2-operation-monitor.md`
- `analysis/pages/A3-water-quality.md`
- `analysis/pages/<page-id>.md`

视觉细节应按 `references/visual-detail-analysis.md` 单独产出，不要只混在页面结构分析中。

如果同时存在需求文档，需求内容必须先按 `references/requirement-prototype-alignment.md` 映射到原型页面、区域、组件或交互。未映射需求不得改变页面结构。

## 页面信息

每张原型图都应记录：

- 页面名称。
- 页面类型。
- 目标尺寸。
- 原型图片文件名。
- 对应业务页面。
- 状态类型：主页面、展开态、选中态、弹窗态、详情态、轨迹态或其他。
- 是否需要复用原型中的图片资产。
- 页面优先级。
 - 实现策略：完整页面、页面状态、弹窗组件、交互触发或暂缓。

## 画布分析

记录：

- 原型宽高。
- 业务画布比例。
- 页面是否为大屏。
- 页面是否需要 cover 缩放。
- 安全区范围。
- 是否存在四周留白、黑边或裁切风险。

## 布局分析

按区域拆解：

### 顶部区域

- 位置。
- 高度。
- 内容。
- 导航结构。
- 标题、时间、天气、用户信息等元素。
- 与主内容区的间距。

### 左侧区域

- 位置。
- 宽度。
- 面板数量。
- 组件类型。
- 数据指标。
- 是否存在折叠菜单或图标导航。

### 中央区域

- 主要视觉内容。
- 背景图或场景图。
- 工艺流程、地图、厂区模型或设备图。
- 热点、标签、连线、动画和下沉入口。
- 中央区域与两侧面板的覆盖关系。

### 右侧区域

- 位置。
- 宽度。
- 面板数量。
- 告警、详情、趋势、排名或状态列表。
- 是否与中央区域联动。

### 底部区域

- 位置。
- 高度。
- 状态栏、时间轴、统计条或快捷入口。
- 是否固定在业务画布底部。

### 弹窗或抽屉

- 触发方式。
- 位置和尺寸。
- 主要内容。
- 关闭方式。
- 是否遮罩背景。

## 组件分析

对每个核心组件记录：

- 组件名称。
- 所属区域。
- 位置。
- 尺寸。
- 样式。
- 数据。
- 交互。
- 是否必须还原。

组件示例：

- 顶部导航。
- 指标卡。
- 毛玻璃面板。
- 趋势图。
- 告警列表。
- 工艺流程节点。
- 场景标签。
- 地图点位。
- 设备状态卡。
- 视频弹窗。

## 颜色分析

记录：

- 主背景色。
- 主品牌色。
- 强调色。
- 状态色。
- 面板背景透明度。
- 描边颜色。
- 文字主色和次级色。
- 图表颜色。

如果无法精准取色，应从原型视觉中估算，并保持色彩关系一致。

如果原型图与 `references/design-spec.md` 的默认色值、透明度、毛玻璃参数或组件样式冲突，必须以原型图为准，并在 `analysis/pages/<page-id>-visual-details.md` 中记录冲突点和采用方案。

## 字体与密度分析

记录：

- 页面标题字号。
- 模块标题字号。
- 指标数字字号。
- 表格和列表字号。
- 行高。
- 字重。
- 文案密度。
- 中文文案长度是否会影响布局。

## 资产分析

记录需要复用的资产：

- 背景图。
- logo。
- 图标。
- 厂区鸟瞰图。
- 三维模型图。
- 地图。
- 设备图片。
- 装饰元素。

每个资产应标注：

- 来源。
- 使用位置。
- 是否允许替代。
- 是否需要裁切、遮罩或调色。

## 交互分析

记录：

- 点击行为。
- hover 状态。
- 选中状态。
- 弹窗。
- 侧边详情。
- 页面跳转。
- 图表联动。
- 告警定位。
- 下钻和返回。
