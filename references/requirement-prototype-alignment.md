# 需求与原型对齐规范

本文件用于指导 Agent 在写代码前判断需求文档内容是否能落到原型图或 Figma 设计中，避免把需求文档中无法对应的内容自由发挥成新模块。

当输入同时包含需求文档和原型图、Figma 链接、Figma Frame、页面截图或导出图时，必须产出：

- `analysis/requirement-prototype-alignment.md`

## 核心原则

- 原型图和 Figma 决定页面结构、模块数量、布局区域和视觉层级。
- 需求文档只用于补充原型已有区域中的业务文案、指标、字段、数据口径和操作说明。
- 需求文档不得直接驱动新增原型中没有的模块、卡片、图表、表格、弹窗、工具栏、页面或交互。
- 无法在原型中找到承载位置的需求，必须进入“未映射需求”或“待确认需求”，不得实现到页面上。

## 映射规则

逐条读取需求文档，并判断每条需求是否能对应到：

- 具体 Figma 链接或 Frame。
- 具体原型页面。
- 顶部导航、左侧菜单、中央主视觉、右侧面板、底部区域、弹窗或抽屉。
- 指标卡、图表、列表、表格、标签、按钮、详情区域或状态图。
- 已有点击、hover、选中、展开、弹窗、轨迹或详情交互。

只有满足以下任一条件时，需求才可实现：

- 原型图中已有对应区域或组件。
- Figma 中已有对应图层或 Frame。
- 需求只是替换或补充原型已有组件的文案、数据或状态。
- 原型中存在明显预留区域，且需求内容与该区域用途一致。

以下情况不得直接实现：

- 需求文档提到功能，但原型没有对应页面、区域或入口。
- 需求内容会导致新增大卡片、大图表、大表格、大弹窗或新页面。
- 需求内容会改变原型布局、模块数量或信息密度。
- 需求内容和原型页面主题不一致。
- 需求文档描述过宽泛，只能推测实现方式。

## 未映射需求处理

对未映射需求：

- 不要删除。
- 不要悄悄实现。
- 记录到 `analysis/requirement-prototype-alignment.md`。
- 在最终回复中说明“未实现，因为原型中无对应承载区域”。

如果用户后续确认要实现，再新增页面模板或要求用户提供补充原型。
