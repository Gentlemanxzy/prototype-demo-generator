# 用户指令规范

本文件约束如何处理用户文本指令、历史对话反馈和多轮改进要求。

## 指令优先级

1. 当前轮用户明确文本指令。
2. 历史对话中已确认且未被覆盖的用户规则。
3. Figma、UI图/原型图、截图、底图和视觉资产。
4. 需求文档中的操作逻辑、数据要求、指标含义和演示重点。
5. 页面模板和设计规范。

当前轮用户明确指令可以覆盖历史规则、Figma/UI图、需求文档、模板和设计规范。覆盖时必须记录原因和影响范围。

历史规则只有在以下情况下失效：

- 用户明确说“这条不用了”“刚才那条作废”“按新的来”。
- 当前轮指令与旧规则冲突，且新指令更具体。
- UI图或需求发生版本更新，用户明确要求以新版本为准。

## 必须产出

每次生成或多轮改进前，必须读取已有 `analysis/user-instructions.md`；如果不存在，必须创建。

`analysis/user-instructions.md` 必须记录：

- 当前轮明确指令。
- 历史有效规则。
- 被当前轮覆盖的旧规则。
- 指令影响的页面、组件、交互、数据或样式。
- 本轮处理结果。

## 多轮改进

当用户在生成后继续提出修改意见时，不要重新从零生成整套页面。必须：

1. 读取现有页面代码和已有分析文件。
2. 更新 `analysis/user-instructions.md`。
3. 判断修改影响范围。
4. 只修改受影响页面、组件、样式、数据或交互。
5. 保留未受影响的已完成效果。
6. 重新截图或检查受影响页面。

## 需求文档角色

需求文档主要用于补充：

- 操作逻辑。
- 指标含义。
- 数据字段。
- 数据范围。
- 单位。
- 图表横纵坐标含义。
- 筛选、切换、弹窗、联动和状态规则。
- 客户演示重点。

需求文档默认不得决定：

- 页面布局。
- 模块数量。
- 视觉样式。
- 背景构图。
- 字体层级。
- 面板位置。
- 点位坐标。
- 页面新增或合并。

除非用户明确说“按需求文档重新组织页面”或“需求文档优先于 UI 图”，否则这些内容必须以用户指令和 Figma/UI图为准。
