# 验收规范

本文件统一约束生成后的截图、视觉、交互、需求映射和交付检查。

## 基本要求

生成完成后必须：

1. 启动本地预览。
2. 打开页面。
3. 截取页面截图。
4. 对照 Figma/UI图/原型图检查差异。
5. 对照分析文件检查布局、视觉、交互、点位和需求映射。
6. 产出 `analysis/visual-check-report.md`。
7. 如果差异明显，继续修改并重新截图。

## 入口可用性检查

检查：

- `workspace/index.html` 直接打开不是空页面。
- 如果使用 Vue/Vite，已执行构建，并确认 `workspace/index.html` 不再依赖 `/src/main.js` 这类开发服务器路径作为唯一入口。
- 如果最终可预览文件位于 `dist/index.html`，根入口必须能跳转到它或加载它的构建资源。
- 页面中引用的 JS、CSS、图片和字体路径均为相对路径，且文件存在。
- 最终回复和 `generation-summary.md` 中的预览入口与实际可打开入口一致。

## Vue/Vite 构建检查

如果使用 Vue/Vite，检查：

- `vite.config.js` 或 `vite.config.ts` 中使用 `plugins: [vue()]`。
- `@vitejs/plugin-vue` 已写入依赖或开发依赖。
- `npm run build` 已成功完成。
- 构建失败时，不得进入截图验收或声明完成。
- 如果没有明确 TypeScript 要求，项目不应默认使用 `vue-tsc -b` 阻塞首版构建。
- 如果没有明确 UI 库或 3D 要求，项目不应默认引入 Element Plus、Tailwind、Three.js 等拖慢首版生成的依赖。

- `analysis/user-instructions.md`：如果用户提供文本指令、反馈或多轮修改要求。
- `analysis/prototype-page-map.md`

## 视口检查

至少检查：

- `1920×1080`
- `1440×900`
- `1366×768`
- 当前浏览器窗口尺寸

非 `1920×1080` 视口下也不得出现明显上、左、右黑边，不得裁切核心导航、菜单、标签、面板和交互区域。

## UI图一致性

检查：

- Figma 链接清单中的所有有效链接都已生成，或登记为弹窗、抽屉、展开态、子页面、切换态等状态实现。
- `analysis/page-scope.md` 中登记的所有主页面都已生成独立页面、路由或可切换视图。
- `analysis/page-scope.md` 中登记的子页面、弹窗、抽屉、展开态、详情态和切换态都已挂到父页面入口，或说明暂缓原因。
- 当用户提交多个页面编号、多个 Figma 链接、多个 UI 图或多个需求文档时，最终产物不能只有一个单页面。
- 顶部、左侧、中央、右侧、底部区域位置接近 UI 图。
- 主要模块数量一致。
- 背景构图、遮罩、透明度、描边、阴影、发光接近 UI 图。
- 顶部导航和右侧卡片字体家族、字号、字重、行高、颜色接近 UI 图。
- `analysis/typography-scale.md` 中的字体表已落实到 CSS，字号没有被通用大屏模板放大。
- 图表、表格、指标卡、告警列表和右侧详情位置接近 UI 图。
- 指标卡、数据卡和右侧详情中的指标名可以单独一行，但数值和单位必须同一行展示，不能出现 `18.5` 与 `℃` 上下换行。
- 底图标签、地图点位、设备热点或工艺节点没有整体偏移。
- 没有新增UI图中不存在的大模块、工具栏或页面。

## 需求映射检查

如果提供需求文档，检查：

- 已产出 `analysis/requirement-prototype-alignment.md`。
- 需求内容已逐条映射到UI页面、区域、组件或交互。
- 需求文档主要被用于操作逻辑、数据要求、指标含义和演示重点。
- 需求文档没有覆盖当前轮用户指令、历史有效用户规则或 Figma/UI图布局视觉。
- 未映射需求已记录。
- 未映射需求没有被自由发挥到界面中。
- 最终回复说明了暂不实现的未映射需求。

## 用户指令检查

如果用户提供文本指令、反馈或多轮修改要求，检查：

- 已产出或更新 `analysis/user-instructions.md`。
- 当前轮明确指令已被执行，或说明暂缓原因。
- 当前轮指令与历史规则、Figma 或需求文档冲突时，已记录覆盖关系。
- 历史有效规则没有被需求文档、模板或设计规范覆盖。
- 多轮修改是在现有页面基础上增量完成，未无故重建或破坏无关页面。
- 最终回复说明了本轮采纳的用户指令和修改范围。

## 交互检查

检查：

- 顶部导航或页面导航可切换，并同步当前选中态和页面/视图内容。
- 左侧业务菜单可用。
- 点击不同底图标签后，右侧详情标题、指标、图表或状态内容对应变化。
- 图表指标切换、时间范围切换或筛选项可用，并同步更新图表数据和当前选中态。
- ECharts 默认没有可见图例；只有 Figma/UI图、需求文档或用户指令明确出现图例、多系列对比说明或图例切换入口时，才显示图例并验收图例切换。
- 弹窗、筛选、按钮、列表行等主要交互可用。
- 展开态、选中态、弹窗态、详情态和轨迹态已按 UI 图映射实现或说明暂缓。
- 模拟数据或演示数据范围合理，不强制在界面明确标注“模拟数据”或“Mock 数据”。

## 差异处理

发现以下问题必须继续优化：

- 页面整体结构不像 UI 图。
- 主要模块数量不一致。
- 未映射需求被实现到界面上。
- 当前轮用户明确指令没有执行，也没有说明暂缓原因。
- 需求文档覆盖了用户指令或 Figma/UI图布局视觉。
- 背景或中央主视觉明显不一致。
- 左右面板位置明显偏移。
- 页面或状态UI图缺失。
- 多个主页面被合并成一个泛化单页面。
- `analysis/page-scope.md` 缺失，或页面范围与用户提交材料不一致。
- `workspace/index.html` 打开为空白，或只依赖开发服务器入口。
- Vue/Vite 项目的 `plugins` 写成 `[vue]` 而不是 `[vue()]`。
- Vue/Vite 构建失败后仍然声明已完成。
- 顶部导航、左侧菜单、tab 或路由无法访问已生成的其他主页面。
- Figma 链接、Frame 或状态图因为没有需求文档对应说明而被跳过。
- 信息密度、字号层级或颜色关系明显偏离UI图。
- 未产出 `analysis/typography-scale.md`，或字体表没有落实到 CSS。
- 导航、面板标题、列表、表格、图表坐标轴、右侧卡片或标签字号明显大于UI图。
- 普通文本、导航、表格、列表、卡片标题或图表坐标轴默认超过 `14-16px`，且没有UI图依据。
- 右侧卡片数值超过 `24px` 或核心 KPI 超过 `32px`，且没有UI图依据。
- 半透明面板、遮罩、边框、阴影、发光或标题栏层级明显偏离UI图。
- 顶部导航只能看不能点。
- 不同标签点击后显示同一个详情。
- 图表缺少需求或 Figma 中明确存在的横坐标、纵坐标、单位、tooltip 或指标切换。
- Figma/UI图、需求文档和用户指令都没有要求图例时，ECharts 仍默认显示图例。
- 指标切换后图表数据、单位、系列或 tooltip 没有变化。
- 有业务含义的图表被实现成 CSS/SVG/图片假图表。
- 页面出现黑边、核心裁切、文字溢出或右侧卡片展示不下。
- 指标数值和单位被拆成上下两行，或单位因为 `display: block`、宽度不足、flex/grid 挤压而换行。
- 点位整体偏移。
